# Unit 11 — 対比と抽象化：「システム思考」を自分の言葉にする

> **対象:** 全員（中2〜一般社会人）
> **ゴール（L3 Teach-Back）:** SD と TOC の切り口の違いを説明でき、両方を統合した「システム思考」を自分の言葉でまとめ、新しい問題へ応用できる
> **所要目安:** 30〜40分
> **準備:** Unit 9・10 で作った「同じ問題」の2つの解答

---

## 1. Hook — 同じ問題を2つのレンズで見た結果

Unit 9（SD）と Unit 10（TOC）で、**同じ問題**を2つの切り口で解きました。例えば「値下げの罠」なら：

| | SD の答え（Unit 9） | TOC の答え（Unit 10） |
|---|---|---|
| 見たもの | 売上と利益の時間差・2つのループ・政策抵抗 | 制約（利益率）・根本原因・対立 |
| 答えたこと | 「なぜ・いつ」利益が減るか | 「どこを・どう」直すか |
| 解決の形 | 利益率のループを強め、効果を待つ | 値下げ以外で売上を増やす仕組み |

**同じ問題なのに、見え方が違いました。** これがこのUnitの出発点です。2つのレンズは「どちらが正しいか」ではなく、**どちらも正しい。見ている面が違う**のです。

## 2. なぜこれを学ぶのか？（Value）

Unit 1〜10 で、たくさんの道具を学びました。

- ストックとフロー・フィードバック・時間の遅れ（SD）
- ボトルネック・5ステップ・CRT・蒸発する雲（TOC）

道具が増えると、**「どの道具を、いつ使うか」** が分からなくなります。このUnitの目的は、道具を「システム思考」という1つの考え方として統合し、**「この問題にはこの切り口」** と選べるようにすることです。

## 3. SD と TOC の関係（Reveal）

### 3.1 2つの切り口の違い

| 軸 | SD（システムダイナミクス） | TOC（制約理論） |
|---|---|---|
| 問い | 構造は**時間とともにどう動くか** | どこを**今**直せば全体が良くなるか |
| 見るもの | ループ・ストック・フロー・遅れ | 制約・根本原因・対立 |
| 得意 | 「なぜそうなるのか」を説明 | 「どこを直すか」を特定 |
| 未来 | 放置の結果を予測（参照モード） | あまり見ない |
| 解決 | ループを切る・フローを変える | 制約を直す・前提を外す |
| 主な道具 | ストックフロー図・ループ図 | 5ステップ・CRT・蒸発する雲 |

### 3.2 相補関係（補い合う）

```
SD: 「なぜ・いつ」問題が起きるか ──→ 構造の全体像が見える
        │
        ▼
TOC: 「どこを・どう」直すか ────→ 改善の焦点が決まる
```

- **SD だけ**だと「構造は分かったが、どこから手をつければ？」となる
- **TOC だけ**だと「直す場所は分かったが、周りの動きへの影響（時間差・副反応）が見えない」

**両方持つと最強。** SD で構造を見て、TOC で制約を直す。

### 3.3 同じ構造の別の顔

実は、SD と TOC は**同じことを別の言葉で**言っている部分があります。

| SD の言葉 | TOC の言葉 |
|---|---|
| 正のループ（成長） | 成長の限界の「伸びる側」 |
| 負のループ（調整・制約） | 制約（ボトルネック） |
| ループを切る | 制約を直す |
| 政策抵抗（対策が打ち消される） | 対立の前提（対策が対立を生む） |

**違う道具でも、見えている「現実の構造」は共通。** これがシステム思考の力です。

## 4. 統合フレーム：「システム思考」のワンストップ（Reveal）

問題にぶつかったときの、統合した流れを作ります。

```
Step0 問題を1文で定義する
   ↓
Step1 参照モード（SD）: このままだとどうなる？ 放置の未来を描く
   ↓
Step2 構造を見る（SD）: ストック・フロー・ループ・遅れを図で描く
   ↓
Step3 制約を特定する（TOC）: どこが全体を決めているか
   ↓
Step4 根本原因を特定する（TOC）: CRT + 因果の検証
   ↓
Step5 対立を解体する（TOC）: 蒸発する雲 → 前提を外す
   ↓
Step6 介入策を設計する（SD+TOC）: ループを切る・フローを変える・前提を外す
   ↓
Step7 確認する（SD+TOC）: 政策抵抗（SD）と FRT（TOC）
   ↓
Step8 Teach-Back（素人に説明）
```

> これを「システム思考のフルコース」と呼びましょう。Unit 7〜10 でバラバラに練習したステップが、ここで1つの流れになります。

## 5. 対比演習 — 自分の問題で統合フレームを回す（Interact）

Unit 9・10 で解いた「同じ問題」を、今度は**統合フレーム（Step0〜8）** で最初からやり直します。

> **やってみよう:** Unit 9・10 の解答を横に置き、統合フレームで「SD の答え」と「TOC の答え」を1枚の図にまとめてみよう。
>
> 例（値下げの罠）:
> - Step1（SD）: 放置すると利益が落ちる
> - Step2（SD）: 正のループ（売上）と負のループ（利益率）の綱引き
> - Step3（TOC）: 制約は利益率
> - Step4（TOC）: 根本原因は「売上＝良し」の思い込み
> - Step5（TOC）: 売上 vs 利益率の対立。前提は「値下げしかない」
> - Step6（統合）: 値下げ以外で売上を増やす（付加価値・客単価）＋利益率ループを強める
> - Step7（統合）: 政策抵抗（単純な値上げは反動）＋ FRT（付加価値の訴求・在庫）
> - Step8: 素人に説明

## 6. 抽象化 — 型を自分の言葉にする（Deepen）

### 6.1 この教材で学んだ「型」をリストアップする

| 型 | 一言 | 使う場面 |
|---|---|---|
| ループ（正/負） | 結果が原因に返る | 増える・減る・安定する理由 |
| ストックとフロー | たまる・流れる | 量の変化を見る |
| 時間の遅れ | 後から効く | やりすぎ・行き過ぎを防ぐ |
| ボトルネック | 一番遅いところ | 全体を速くする |
| 5ステップ | 見つける→活用→従属→強化→繰り返す | 改善の手順 |
| 根本原因（CRT） | 1つに絞る | 対策を効率化 |
| 蒸発する雲 | 前提を外す | 対立を両立させる |
| 政策抵抗 | 対策が打ち消される | 対策の失敗を防ぐ |

### 6.2 「システム思考」を自分の言葉で定義する

次のテンプレで、「システム思考とは何か」を自分なりの言葉で書いてみよう。

```
私にとって「システム思考」とは、
【物事を（　　　　　　）として見ることで、
　（　　　　　　）を（　　　　　　）できる考え方】

理由: Unit（　　）で学んだ（　　　　　　）が、いちばん実感できたから
例: （　　　　　　）という問題で、こんな風に使えた
```

> **書き方のヒント:**
> - 「ぐるぐる回る関係」「流れ」「制約」「根本原因」などの言葉を使う
> - 例を必ず1つ入れる（抽象だけでは身につかない）
> - 比喩を1つ（「物事をブランコのように見る」等）

## 7. Check — 確かめてみよう

1. SD と TOC は、それぞれ問題をどんな視点で見る？
2. 「どちらが正しい」でなく、何が大事？
3. SD と TOC で「同じ構造を別の言葉で言っている」例を1つ。
4. 統合フレームで、SD の道具と TOC の道具が「交代」で出てくる順番は？

> **答え（下を見る前に自分で）:**
> 1. SD: 時間とともにどう動くか（振る舞い）、TOC: 今の構造（制約・根本原因）
> 2. 見ている面が違う。両方持つと「なぜ・いつ」と「どこを・どう」が揃う
> 3. 例: SDの「負のループ（制約）」＝TOCの「ボトルネック」／SDの「ループを切る」＝TOCの「制約を直す」
> 4. 参照モード→構造（SD）→制約→根本原因→対立（TOC）→介入策→確認（SD+TOC）

## 8. よくある誤解（Misconceptions）

| 誤解 | 正しい理解 |
|---|---|
| 「SD と TOC はどちらか選ぶもの」 | 別の道具ではなく、同じ現実の違う面。両方使うと最強 |
| 「システム思考＝難しい図を描くこと」 | 図は手段。目的は「問題の構造を見て、効率よく直す」こと |
| 「型を覚えれば問題が解ける」 | 型はヒント。**当てはめではなく、構造を見る目**が本質 |
| 「抽象化＝難しい言葉を使うこと」 | 抽象化は「共通の型を見つける」こと。簡単な言葉で言えるのが理想 |

## 10. Teach-Back — 素人に説明しよう（最終ゴール）

「システム思考とは何か」を、システム思考を知らない人に説明しよう。

1. **何の話か:** 「物事を構造で見ると、問題がよく見える」という話
2. **部品は何か:** ループ・ストック・ボトルネック・根本原因（から必要なもの）
3. **どう繋がるか:** 見る（SD）→ 直す（TOC）→ 解く（根本原因・対立）
4. **例:** 自分が Unit 9・10・11 で解いた問題
5. **よくある誤解:** SDとTOCは選ぶものではない
6. **素人への一言:** 「物事をブランコみたいに見るんだよ。押すと返ってくる。どこを押すか（制約）を見つけて、返ってくる（時間差・副反応）ことも考える」

---

## まとめ（Takeaway）

- **SD = 見る**（時間とともにどう動くか）、**TOC = 直す**（今の構造・制約・根本原因）
- 同じ現実を別の面から見ている。**両方持つと最強**
- 統合フレーム（Step0〜8）で、SD と TOC の道具を1つの流れに
- 抽象化 = 共通の型を見つけること。簡単な言葉で言えるのが理想
- **「システム思考」＝物事を構造で見て、効率よく直す一生ものの考え方**

> **おめでとう！** これで Unit 1〜11 の全コースが完了です。最後に自分の言葉で「システム思考」を説明できたら、この教材のゴール達成です。
