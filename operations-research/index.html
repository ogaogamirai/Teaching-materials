⚡ 0. なぜ素朴なプログラミングでは解けないのか？

スタッフ4名、1週間のシフト表（日勤・夜勤・休みの28マス）。
すべての組み合わせは $3^{28} \approx 22\text{兆通り}$ です。スタッフが8人の1ヶ月（30日）になれば $3^{240} \approx 10^{114}$ 通りを超え、全宇宙の原子の数（$10^{80}$）を凌駕します。

この問題は計算量理論において「NP困難（NP-hard）」と呼ばれ、すべての選択肢を調べる総当たり（ブルートフォース）は物理的に不可能です。人間が毎月パズルを組んで頭を抱えるのも当然です。

核心の問い：
「コンピュータは、22兆通りを調べずに、一体どうやって0.02秒で全制約を満たす解を見つけているのか？ 特に変わったことをしているのか？」

🏛️ 1. CP-SAT誕生のドラマ：2つの流派の「奇跡の合体」

かつてコンピュータサイエンスには、似ているようで交わらない2つの世界がありました。

制約プログラミング (CP)

「夜勤の翌日は日勤禁止」「全員バラバラの値」など、人間の言葉に近い柔軟な制約をそのまま書ける。しかし探索が遅く、大規模問題で息切れした。

SATソルバー (命題論理)

「0と1の論理式」しか扱えない。しかし、CPUのバグ検証などで培われた超人的な推論エンジン（CDCL）を持ち、数百万変数を一瞬で解く怪物。

2010年代半ば、Google OR-Toolsの開発チーム（Laurent Perronら）が歴史的ブレイクスルーを起こしました：
「表側はCPの豊かな表現力で人間が書き、ツールが裏でそれを全部『0と1の命題論理』に自動分解して、最強のSATエンジン（CDCL）で解かせればいい！」
これが現在、世界標準となっている CP-SAT です。

🧠 2. 衝突駆動節学習（CDCL）：ブラックボックス（ソルバー）の完全解体

Pythonで書くコードはたった1行、status = solver.Solve(model) だけです。
しかし、この関数の内部では「4つの専門部署が働く超知性チーム」がミリ秒単位で火花を散らしています。
この仕組みを知ると、「なぜあのコードを書くのか」「どう書けばソルバーが爆速で解いてくれるのか」が手にとるように分かるようになります！

🏢 ソルバー内部で働く「4つの専門部署」（自動化工場）

22兆通りの迷路に突入したソルバーは、以下のサイクルを1秒間に何万回も回して正解へ追い詰めています：

① プリソルバー (Presolver)
【仕分け屋】

探索前に、自明なマス（確定休など）を即座に固定し、不要な選択肢を削ぎ落とす。
探索空間を一瞬で数万分の一に圧縮！

② 探索ヒューリスティクス
【直感のベテラン刑事】

左上から順番に試すのではなく、「一番制約がキツい危険なマス（夜勤枠など）」から優先的に仮定する（VSIDS技術）。

③ 制約伝播 (Propagator)
【ドミノ倒しの名手】

1マスが決まった瞬間、「夜勤明けの翌日日勤禁止」「1日1人」の連鎖で、周囲の何十マスもの候補を自動確定（単位伝播）！

④ 衝突学習 (CDCL心臓部)
【失敗を糧にする参謀】

矛盾（衝突）に激突した時、犯人の組み合わせを特定して「新ルール（学習節）」を自作。5手前まで一気に大脱出ジャンプ！

💡 中身の理解がコードに直結する！ 現場のプログラミング4箇条

ソルバーの内部メカニズム（伝播と学習）が分かると、なぜPythonコードでその書き方をするのかが完全に腑に落ちます：

Q1. なぜ AddExactlyOne を使うのか？

単に足して1と書くより、AddExactlyOne と書いた方が、部署3（伝播エンジン）が「誰か1人決まったら残り全員を0にする」というドミノ倒しを超高速に発動できるからです。

Q2. なぜ連休制約で AddBoolAnd を使うのか？

補助フラグとANDを束縛することで、部署4（CDCL）が「飛び石ばかりの組み合わせ」にぶつかった瞬間、一網打尽にする学習節を自律生成できるからです。

Q3. なぜ掛け算や割り算を避けるのか？

ソルバーの本質は「0と1の命題論理（SAT）」です。足し算や不等式（線形）で書いてあげると、部署1（プリソルバー）が一瞬でSATの節に分解できるからです。

Q4. なぜ二分探索で最適解が出るのか？

CDCLが学習節の力で「白黒判定（YES/NO）」を0.001秒で返せるからこそ、不満度ペナルティのピストン締め上げ（MaxSAT）が成立するからです。

⚖️ 3. 白黒判定器がなぜ「柔軟なシフト」を作れるのか？

ここで極めて鋭い疑問が生まれます：
「CDCLはYESかNOか（満たす解があるか否か）を判定するだけの論理マシンなのに、なぜ現場の柔軟な希望や妥協（最適化）ができるのか？」

答え：MaxSAT と 締め上げ二分探索
CDCLを単発で使うのではなく、「不満度（ペナルティ）を締め上げるピストン」として超高速連打しています。
1. 問う: 「不満度 50点以下 で全員のルールを守れるシフトはあるか？」
　 ➔ CDCL: YES! (解Aを発見: 0.002秒)

2. 問う: 「じゃあ、不満度 20点以下 はあるか？」
　 ➔ CDCL: YES! (解Bを発見: 0.003秒)

3. 問う: 「じゃあ、不満度 5点以下 はあるか？」
　 ➔ CDCL: NO! (数学的に不可能です: 0.001秒)

4. 判定: 「解B（不満度20点）が、人類が取りうる最もマシな最高妥協案（最適解）だ！」

CDCLがミリ秒単位でYES/NOを返せるからこそ、二分探索で最良の妥協点を一瞬で絞り込めるのです。

第3段階：生の声の該当するマスに「1」を立てる（要望マトリクスの誕生）

🐍 Pythonコードでこのマトリクスを定義する具体例（2つの王道スタイル）

この「0と1の表」は、Pythonでは以下のどちらの形式でも直感的に書くことができます：

スタイルA: 見た目そのままの2次元配列 (0/1 Matrix) 
# スタッフ × 日付の「希望休(O)」マトリクス
#          月, 火, 水, 木, 金, 土, 日
request_matrix = {
    "Alice":   [0,  0,  1,  0,  0,  0,  0],  # 水休
    "Bob":     [0,  0,  0,  0,  0,  1,  1],  # 土日休
    "Charlie": [1,  0,  0,  0,  0,  0,  0],  # 月休
    "Dave":    [0,  0,  0,  0,  0,  0,  0],  # なし
}

# 利用側: マトリクスで1のマスだけペナルティに変換
for s, row in request_matrix.items():
    for d_idx, is_req in enumerate(row):
        if is_req == 1:
            d = days[d_idx]
            penalties.append(10 * (1 - x[s, d, "O"]))
スタイルB: 実務で最も好まれる「辞書形式」 (Sparse Map) 
# (スタッフ, 日付) ➔ 希望シフト のマッピング
# ※ 0（こだわりなし）は省略できるため実務で超便利！
requests = {
    ("Alice",   "水"): "O",  # 水曜休み
    ("Bob",     "土"): "O",  # 土曜休み
    ("Bob",     "日"): "O",  # 日曜休み
    ("Charlie", "月"): "O",  # 月曜休み
    ("Dave",    "金"): "N",  # 金曜夜勤手当
}

# 利用側: 辞書から直接ペナルティに変換
for (s, d), desired_shift in requests.items():
    penalties.append(10 * (1 - x[s, d, desired_shift]))

第4段階：Pythonコードでの保持方法と「不満度（ペナルティ）の数式化」

Pythonプログラムでは、この要望を (スタッフ, 日付, 希望シフト) をキーにした辞書やタプルリストで直感的に保持します：

# 1. 現場から集まった要望リスト（これが要望マトリクスの実体！） requests = [ {"staff": "Alice", "day": "水", "shift": "O", "weight": 10}, # 水曜休 {"staff": "Bob", "day": "土", "shift": "O", "weight": 10}, # 土曜休 {"staff": "Bob", "day": "日", "shift": "O", "weight": 10}, # 日曜休 {"staff": "Charlie", "day": "月", "shift": "O", "weight": 10}, # 月曜休 {"staff": "Dave", "day": "金", "shift": "N", "weight": 10}, # 金曜夜勤 ] # 2. マトリクスからペナルティ（目的関数）への自動変換！ penalties = [] for req in requests: s = req["staff"] d = req["day"] sh = req["shift"] w = req["weight"] # x[s, d, sh] が 1（希望通り）なら、(1 - 1) = 0点（不満なし） # x[s, d, sh] が 0（叶わず）なら、(1 - 0) * weight = 10点（ペナルティ発生！） penalties.append(w * (1 - x[s, d, sh])) # 全員の不満合計を最小化せよ！ model.Minimize(sum(penalties))
💡 ここが美しさの頂点！
w * (1 - x) という極めてシンプルな1行の数式で、
「叶えばペナルティ0、叶わなければペナルティ加算」 という人間の「わがまま・願望」が完璧に数理化されました。
あとはCP-SATが、第3章で学んだMaxSAT二分探索で「不満ペナルティの合計が最も小さくなる妥協シフト」を一瞬で探索してくれるのです！

sum(x[s, d, "N"] for d in days) <= 2
)
① 「1人1日1シフト」の絶対原則（排他） ［C1］ 基本中の基本

人間の言葉：「同じ日に日勤と夜勤を両方やったり、出勤なのに休みになったりするのは物理的にあり得ない！」

💡 数学的判定式（音読）： 日勤フラグ ＋ 夜勤フラグ ＋ 休日フラグ ＝ ちょうど1
$$x_{s, d, \text{D}} + x_{s, d, \text{N}} + x_{s, d, \text{O}} = 1$$
# CP-SATなら専用メソッドで一撃（内部でCDCLが超高速に排他伝播） for s in staff: for d in days: model.AddExactlyOne([x[s, d, shift] for shift in ["D", "N", "O"]])
② 「毎日の必要人数の確保」（縦の合計） ［C2］ 現場の維持

人間の言葉：「毎日必ず、日勤に1人、夜勤に1人は現場にいなければ仕事が回らない！」

💡 数学的判定式（音読）： 全スタッフの日勤フラグを足し合わせた合計が 1 に等しい
$$\sum_{s \in \text{Staff}} x_{s, d, \text{D}} = 1, \quad \sum_{s \in \text{Staff}} x_{s, d, \text{N}} = 1$$
for d in days: model.Add(sum(x[s, d, "D"] for s in staff) == 1) model.Add(sum(x[s, d, "N"] for s in staff) == 1)
③ 「夜勤の翌日は日勤禁止」（隣接インターバル規制） ［C3］ 健康・労働衛生

人間の言葉：「朝まで夜勤をやった数時間後に、そのまま日勤に入るのは過労死ラインだから絶対NG！」

💡 数学的判定式（音読）： 「今日夜勤(1)」かつ「明日日勤(1)」の同時成立を禁止（足して1以下）
$$x_{s, d, \text{N}} + x_{s, d+1, \text{D}} \le 1$$
for s in staff: for d in range(len(days) - 1): model.Add(x[s, days[d], "N"] + x[s, days[d+1], "D"] <= 1)
🌟 ④ 「どのスタッフも、一週間に2連休を最低1回取らせる」（連休制約） ［C4］ 超頻出・応用パズル

人間の言葉：「飛び石連休ばかりだと旅行にも行けず疲れが取れない。一週間のうち必ずどこかで『2日連続の休み』を取らせて！」

💡 思考のステップ（補助変数 ＋ AND ＋ OR）：
1. 2連休になり得るペアは、週に6箇所（月火, 火水, 水木, 木金, 金土, 土日）。
2. 各ペアについて「両日休みか？」を表すスイッチ（補助ブール変数 $c_{s, d}$）を作る。
3. $c_{s, d} \iff (x_{s, d, \text{O}} \land x_{s, d+1, \text{O}})$ （両日休みならスイッチON）
4. 全6ペアのうち「少なくともどれか1つがON」： $\sum_{d=0}^{5} c_{s, d} \ge 1$
for s in staff: two_off_pairs = [] for d in range(len(days) - 1): # 補助変数: このペアが2連休か？ pair_flag = model.NewBoolVar(f"two_off_{s}_{days[d]}_{days[d+1]}") # pair_flag が 1 になるのは「今日が休み」かつ「翌日も休み」のとき model.AddBoolAnd([x[s, days[d], "O"], x[s, days[d+1], "O"]]).OnlyEnforceIf(pair_flag) two_off_pairs.append(pair_flag) # 6つのペアのうち、最低1回は成立していなければならない！ model.Add(sum(two_off_pairs) >= 1) # または model.AddBoolOr(two_off_pairs)
⑤ 「3連勤以上は禁止」（連続勤務の上限） ［C5・応用］ 過労防止

人間の言葉：「3日連続で勤務（日勤または夜勤）させるな！ 3日間の窓の中に最低1日は休みを入れろ！」

💡 数学的判定式（音読）： 任意の連続する3日間において、休みの合計が 1日以上
$$x_{s, d, \text{O}} + x_{s, d+1, \text{O}} + x_{s, d+2, \text{O}} \ge 1 \quad (\forall d)$$
for s in staff: for d in range(len(days) - 2): model.Add(x[s, days[d], "O"] + x[s, days[d+1], "O"] + x[s, days[d+2], "O"] >= 1)
補則 「夜勤は1人最大2回まで」（公平ハード上限） ［CF］ テンプレート制約5

人間の言葉：「夜勤の偏りはペナルティ（第6章）で滑らかに扱うのが基本。どうしても割らせない上限だけ、ハード制約として天井を打つ！」

💡 数学的判定式（音読）： 1週間の夜勤フラグの合計が 2 以下
$$\sum_{d} x_{s, d, \text{N}} \le 2$$
for s in staff: model.Add(sum(x[s, d, "N"] for d in days) <= 2)

対応：テンプレート制約5・OPTIOのunsat IDは CF。第6章レベル③の「不公平ペナルティ（ソフト版）」と使い分ける。

⑥ 「個人の希望休・わがまま」（ソフト制約 ＝ ペナルティ化） ［C6］ 柔軟な最適化

人間の言葉：「Aliceは水曜日に休みたい。どうしても無理なら仕方ないけど、できる限り叶えて！」

💡 数学的判定式（音読）： 叶わなかった時（$x=0$）にペナルティ加算、叶えば（$x=1$）ペナルティ0
$$\text{Penalty} = \text{Cost} \times (1 - x_{s, d, \text{O}})$$
penalties = [] # Aliceの水曜休み希望（叶わなければ +10点 の不満ペナルティ） penalties.append(10 * (1 - x["Alice", "水", "O"])) # ソルバーに「不満の合計を最小にせよ！」と命じる（MaxSAT二分探索が始動） model.Minimize(sum(penalties))

🎓 第5章の重要チェックポイント（制約構築の黄金律）

  • ExactlyOne: 排他選択は AddExactlyOne([x, y, z]) または sum(...) == 1。
  • 時間軸スライス（スライディングウィンドウ）: 「2連休」や「最大3連勤」は、連続する日付ブロックをループで回して不等式を立てる。
  • ハード制約とソフト制約の境界: 破綻させないための絶対制約は Add(...)、妥協を許す希望は次章（第6章）の「ペナルティ（目的関数）」へ回す。

👉 次の第6章へ進もう: 制約が決まったら、次は「不満度」や「偏り」をどのように数値化し、ソルバーに最小化させるかという目的関数の設計術を学びます！

🎯 6. 【不満度の測定と設計】人間の心理を数理モデルにする技術

ハード制約（人数確保や夜勤明け日勤禁止）は「違反か適合か（0か1か）」の白黒判定でした。
しかし、現場のスタッフの希望や公平性は「グラデーション（感情や痛みの度合い）」です。
この人間の心理をいかにして「目的関数（最小化すべきペナルティ）」として美しく測定・設計するか、その4大アプローチを解剖します。

レベル①：基本測定式「叶えば0点、叶わなければ加算」 基本の型

心理の言語化：「休みを希望したのに出勤にされたら悲しい。希望が通ったら満足（不満ゼロ）！」

💡 測定式（音読）： 不満度 ＝ 1 − 実際のシフト変数
$$\text{Penalty} = 1 - x_{s, d, \text{希望シフト}}$$
  • 希望が叶った場合（$x = 1$）： $1 - 1 = 0$ （不満度 0点）
  • 希望が蹴られた場合（$x = 0$）： $1 - 0 = 1$ （不満度 1点 発生！）
# Aliceの水曜休みが叶わなければペナルティ加算 penalties.append(1 - x["Alice", "水", "O"])
レベル②：優先度の重み付け（Weight）「みんなの希望は平等ではない」 現場の必須機能

心理の言語化：「子供の冠婚葬祭（絶対に休みたい！）と、なんとなく趣味で休みたい希望を同じ扱いにされたら困る！」

💡 測定式（音読）： 不満度 ＝ 重み係数 $w$ × ( 1 − 実際のシフト変数 )
$$\text{Total Penalty} = \sum_{(s, d)} w_{s, d} \times (1 - x_{s, d, \text{希望}})$$
  • 命がけの希望（冠婚葬祭・通院）： 重み $w = 100$
  • 普通のお休み希望（キャンプ・旅行）： 重み $w = 10$
  • 通ったら嬉しい程度の軽い希望： 重み $w = 2$
# 重み付きペナルティの登録 penalties.append(100 * (1 - x["Alice", "水", "O"])) # ピアノ発表会（重み100） penalties.append(10 * (1 - x["Bob", "土", "O"])) # キャンプ（重み10）
🌟 レベル③：不公平さの測定（夜勤回数の偏り・絶対値ペナルティ） プロのモデリング

心理の言語化：「私だけ今週夜勤が3回も入っているのに、あの人は1回だけなんて不公平で耐えられない！」

💡 測定式（音読）： 理想回数（例: 2回）からのズレ（絶対値誤差）をペナルティにする
$$\text{Night Diff}_s \ge |\text{実際の夜勤回数}_s - \text{理想の回数}|$$ 線形化テクニック：補助変数 $\text{diff}_s$ を置き、2本の不等式で絶対値を挟み込む！
$$\text{diff}_s \ge \sum_d x_{s, d, \text{N}} - \text{Target}, \quad \text{diff}_s \ge \text{Target} - \sum_d x_{s, d, \text{N}}$$
target_night = 2 # 1人あたりの理想夜勤回数 for s in staff: actual_night = sum(x[s, d, "N"] for d in days) diff = model.NewIntVar(0, 7, f"diff_{s}") # diff >= |actual - target| を2式で表現（絶対値の線形化） model.Add(diff >= actual_night - target_night) model.Add(diff >= target_night - actual_night) # ズレ1回につき 20点 の不公平ペナルティを加算！ penalties.append(20 * diff)
レベル④：痛みの集中防止（累乗・多段階ペナルティ） 合意形成の極致

心理の言語化：「1回我慢するのは譲り合いだけど、2回も3回も自分だけ蹴られたら退職します！」

💡 設計思想： 不満は線形（10点, 20点, 30点）ではなく、二乗（10点 ➔ 40点 ➔ 100点）で爆発する。
「1人に我慢を集中させるくらいなら、全員で1回ずつ痛みを分け合う方がマシ」という優しい妥協解をソルバーに選ばせる。
# 違反回数に応じてペナルティ係数を跳ね上げる（痛みの分散） # 1回目の未達: +10点 / 2回目の未達: +30点 / 3回目の未達: +80点... # ➔ ソルバーは「特定の人に我慢が集中する解」を避けて「全員平等に1回ずつ我慢する解」を選ぶ！

📊 不満度測定の全体アーキテクチャまとめ

測定対象 人間の心理・現場の不満 数理モデルでの表現 ソルバーの行動

🐍 7. 【実践】Python (Google OR-Tools) で書く黄金の型

世界中の現場で使われている、Google OR-Tools CP-SATの実装コードです。どんな問題もこの「黄金の3ステップ」で解けます。

from ortools.sat.python import cp_model

# 0. 基本データ（スタッフ・曜日）
staff = ["Alice", "Bob", "Charlie", "Dave"]
days = ["月", "火", "水", "木", "金", "土", "日"]

# 1. モデルの初期化
model = cp_model.CpModel()

# --- ステップ①：変数を置く（何を決めるのか？） ---
# x[スタッフ, 日, シフト] in {0, 1}
x = {}
for s in staff:
    for d in days:
        for shift in ["D", "N", "O"]:
            x[s, d, shift] = model.NewBoolVar(f"x_{s}_{d}_{shift}")

# --- ステップ②：ハード制約を敷く（鉄の掟） ---
# [C1] 1人1日1シフトのみ（日・夜・休の排他）
for s in staff:
    for d in days:
        model.AddExactlyOne([x[s, d, shift] for shift in ["D", "N", "O"]])

# [C2] 毎日、日勤1名、夜勤1名
for d in days:
    model.Add(sum(x[s, d, "D"] for s in staff) == 1)
    model.Add(sum(x[s, d, "N"] for s in staff) == 1)

# [C3] 夜勤の翌日は日勤禁止！（足して1以下）
for s in staff:
    for d in range(len(days) - 1):
        model.Add(x[s, days[d], "N"] + x[s, days[d+1], "D"] <= 1)

# [C4] どのスタッフにも一週間に最低1回の2連休！（補助変数＋AND＋OR）
for s in staff:
    two_off = []
    for d in range(len(days) - 1):
        pair_flag = model.NewBoolVar(f"two_off_{s}_{d}")
        model.AddBoolAnd([x[s, days[d], "O"], x[s, days[d+1], "O"]]).OnlyEnforceIf(pair_flag)
        two_off.append(pair_flag)
    model.Add(sum(two_off) >= 1)

# [CF] 公平性：夜勤は1人最大2回まで（テンプレート制約5）
for s in staff:
    model.Add(sum(x[s, d, "N"] for d in days) <= 2)

# --- ステップ③：ソフト制約（目的関数：ペナルティ最小化） ---
penalties = []
penalties.append(10 * (1 - x["Alice", "水", "O"])) # Alice水曜休みの希望
penalties.append(10 * (1 - x["Bob", "土", "O"])) # Bob土曜休みの希望
penalties.append(10 * (1 - x["Bob", "日", "O"])) # Bob日曜休みの希望
penalties.append(10 * (1 - x["Charlie", "月", "O"])) # Charlie月曜休みの希望
penalties.append(10 * (1 - x["Dave", "金", "N"])) # Dave金曜夜勤の希望
model.Minimize(sum(penalties))

# 実行！
solver = cp_model.CpSolver()
status = solver.Solve(model)

🌍 8. 【応用】あらゆるビジネス課題への横展開

この「CP-SATの型（変数・制約・目的）」は、シフト表だけでなく、あらゆる現実問題にそのままトランスファー（移植）できます。

🚚 配車・巡回ルート (VRP)

「トラック5台で20箇所に配送する。積載量上限と時間指定を守り、走行距離を最小化せよ」。

変数: $x_{i, j, k}$（トラックkが拠点iからjへ走るか）

🎒 予算・機能配分 (Knapsack)

「予算1億円、エンジニア30人月。30個の機能候補から、費用対効果が最大の組み合わせを選べ」。

変数: $x_{i}$（機能iを採用するか0/1）

⏱️ 工程計画 (RCPSP)

「タスクAが終わらないとタスクBは着手できない。重機が2台しかない制約下で最短工期を求めよ」。

変数: $t_{i}$（タスクiの開始時刻）
