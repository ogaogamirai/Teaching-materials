## 1. Hook — 「人手不足」をまず疑ってみる

職場では、こんな問題がよくあります。

- 会議ばかりで仕事が進まない
- 残業が減らない
- 売上が伸びない
- 値下げしたのに利益が減った

どれも「人が足りない」「努力が足りない」と片付けられがちです。でも本当にそうでしょうか？

**このUnitでは「人のせい」「努力のせい」にする前に、問題を「時間とともにどう動くか」という視点で見ます。** これがシステムダイナミクス（SD）の切り口です。

## 2. SD の切り口とは（このUnitの主軸）

Unit 1〜4 で学んだ道具を、**問題解決の道具として**使い切ります。

| SD の道具 | 問題解決での使い方 |
|---|---|
| ストックとフロー（Unit 2） | 「何がたまっているか・何が流れているか」で問題の正体を見る |
| フィードバックループ（Unit 3） | 「増えるともっと増える（正）」「増えると抑える（負）」の構造を見る |
| 時間の遅れ（Unit 4） | 「対策の効き目が後から出る」ことを織り込む |

SD の問題解決は、次の4つのステップが核になります。

### ① 参照モード（Reference Mode）—「このままだとどうなる」を描く
問題を「今」だけではなく **過去→現在→未来** のグラフで見る。放置するとどう悪化するかを、まず描く。

### ② 構造を見る — ループ・ストック・遅れを描く
問題を生んでいる「ぐるぐるの構造」を図で描く。正のループ・負のループ・遅れを見つける。

### ③ 介入点（レバレッジポイント）— ループのどこに手を入れるか
- 正の悪循環ループを**切る**
- 負の調整ループを**強める**（活用する）
- ストックの入りフロー / 出フローを**変える**

### ④ 政策抵抗（Policy Resistance）— 対策が打ち消されないか
「対策を打っても、既存のループに吸収されて効かない」ことがある。これを**事前に予見する**。

## 3. SD の切り口 vs TOC の切り口（見え方の違い）

Unit 10 で同じ問題を TOC の切り口で解きます。先に違いを知っておくと、見比べが効率的です。

| 視点 | SD（このUnit） | TOC（Unit 10） |
|---|---|---|
| 見る対象 | 時間とともにどう動くか（振る舞い） | 今の構造（制約・根本原因） |
| 切り口 | ループを切る・フローを変える | 制約を特定して直す |
| 未来 | 「このままだとどうなる」をまず描く | （あまり見ない） |
| 対策の副反応 | 政策抵抗（既存ループに打ち消される）を予見 | FRT で確認 |
| 時間の遅れ | 効果が遅れる・行き過ぎることを設計に組み込む | 考慮はする |

## 5. SD の問題解決フレーム（このUnitの共通ステップ）

```
Step1 参照モードを描く: このままだとどうなる？ 過去→現在→未来のグラフ
Step2 構造を見る: ストック・フロー・正負ループ・遅れを図で描く
Step3 介入点を探す: どのループを切る？ どのフローを変える？
Step4 政策抵抗を予見: 対策は既存ループに打ち消されないか？
Step5 介入策を設計する（SD流の解決策）
Step6 Teach-Back（自分の選んだ題材で説明）
```

> このUnitでは「制約を特定する」「CRT」「Injection」などの TOC 道具は**意図的に使いません**。SD だけの目で見て、どこまで解けるかを体験します。Unit 10 で TOC の目をかけると、見え方がどう変わるかが分かります。

## 6. 例題（EX9: 値下げの罠）— 解答つき

値下げで「売上は増えたのに利益が減った」問題を、**SD の4つのステップだけ**で解いてみる。

### Step1: 参照モード（このままだとどうなる）

まず、過去→現在→未来のグラフを描く。

![fig:参照モード — 売上（青）は表面上昇するが、利益（赤）は減少傾向。放置すると破線のように利益が急落し赤字に転落する予測](figures/unit9_reference_mode.svg)

「今」は売上（フローIN）が伸びて見えるが、**利益（ストック）は減少傾向**。このままだと、さらに値下げ競争に巻き込まれ、利益が落ち続けると予測できる。

### Step2: 構造を見る（ストック・ループ・遅れ）

**ストックとフロー（Unit 2）:**

```
売上（フローIN）──▶ [利益（ストック）] ◀── 費用（フローOUT）
```

**2つのループ（Unit 3）:**

```
【正のループ】 値下げ → 販売数増 → 売上増 → さらに値下げ
【負のループ】 値下げ → 利益率減 → 利益減 → 投資できない → 品質低下 → 販売減
```

**時間の遅れ（Unit 4）:** 正のループ（売上増）は**すぐに見える**が、負のループ（利益率減）は**後から効いてくる**。だから「今は売れてるから大丈夫」と錯覚する。

### Step3: 介入点を探す

ループのどこに手を入れるか、SD の目で見る。

- **正のループを切る?** 値下げのループを止める（値下げ競争から降りる）
- **負のループを強める?** 利益率を守る仕組みを作る（安売りしない・付加価値で売る）
- **フローを変える?** 費用（発送・返品）のフローOUTを減らす

→ SD の答え: 「売上を増やす」より「**利益（ストック）を増やすフローを変える**」＝利益率のループを強める。

### Step4: 政策抵抗を予見

「値上げすればいい」という対策を打っても、**既存のループに打ち消されないか**を予見する。

```
値上げ → 販売数が減る（正のループの反動） → 売上が減る → 焦って再び値下げ
```

→ 単純な「値上げ」は政策抵抗に遭う。**価格に見合う価値（品質・サービス）を同時に上げる**ことで、販売数の減少を防ぎながら利益率を上げる、という介入が SD 的。

### Step5: 介入策の設計（SD流）

- ストック（利益）を増やすには、入りフロー（売上）を増やす OR 出フロー（費用）を減らす
- 利益率の負のループを強める（値下げ競争から降りる・付加価値で差別化）
- 遅れを織り込んで、効果が出るまで「待つ」設計（短期の売上減少を許容）

### Step6: Teach-Back

「値下げの罠は、売上（フロー）の正のループが先に見えて、利益（ストック）の負のループが遅れて効くこと。だから、利益率を守るループを強めて、効果が遅れることを織り込んで待つ、が SD の答え」

## 7. やってみよう — 自分の題材で（SD の目だけで）

EX4・EX5・EX6・EX9 から1つ選び、SD フレーム（Step1〜6）を1本通しでやる。

> **やってみよう:** 選んだ題材で、参照モードのグラフ→構造図→介入点→政策抵抗、と進めてみよう。**TOC の道具（CRT・Injection）は使わずに**、SD の目だけでどこまで解けるか試してみよう。

## 8. Check — 確かめてみよう

1. 参照モードとは何を描くもの？
2. 「政策抵抗」とは、何が起きること？
3. SD の介入点にはどんな種類がある？（3つ）
4. 値下げの罠で、SD が見る「2つのループ」は？

> **答え（下を見る前に自分で）:**
> 1. 「このままだとどうなるか」の過去→現在→未来のグラフ
> 2. 対策が既存のループに打ち消されて、効かないこと
> 3. 正の悪循環ループを切る・負の調整ループを強める・フローを変える
> 4. 正のループ（値下げ→売上増）と負のループ（値下げ→利益率減）

## 9. Teach-Back — 素人に説明しよう

自分の選んだ題材で、SD の切り口を素人に説明しよう。テンプレ:

1. **何の話か:** 「問題を時間とともにどう動くかで見る」話
2. **部品は何か:** 参照モード・ストック・フロー・ループ・遅れ・介入点・政策抵抗
3. **どう繋がるか:** まず放置の未来を描く → 構造を見る → 介入点に手を入れる → 政策抵抗を予見
4. **図はどこを見ればいいか:** 参照モードのグラフと、ループの図
5. **よくある誤解:** 対策はすぐ効く、とは限らない（遅れと政策抵抗）
6. **素人への一言:** 「値下げの罠だよ。売上（入る）はすぐ増えるけど、利益（たまる）は遅れて減る。たまる方を見て、後から効くことを待つ」

## まとめ（Takeaway）

- SD の切り口 = **問題を「時間とともにどう動くか」で見る**
- 4つのステップ: **参照モード → 構造 → 介入点 → 政策抵抗**
- 介入点: 正のループを切る・負のループを強める・フローを変える
- 「対策が効かない」のは、**政策抵抗**（既存ループに打ち消される）かもしれない
- **対策の効果は遅れる。** 待つ設計を入れるのが SD 流
- 次回は**同じ問題**を TOC の切り口で解き、見え方を比べる

> **次回予告 (Unit 10):** 同じ問題を TOC の切り口（制約・CRT・Injection）で解く。SD と見比べよう。
