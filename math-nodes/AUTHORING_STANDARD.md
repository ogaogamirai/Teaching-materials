# 個別教材 作成基準

42ノード教材を、短くても理解と再現が成立する形で作るための基準。

## 1. 正本と前提

- ノードID、`prerequisites`、`diagnostic_query` は `ontology/math_euler_complete_ontology.json` から転記する。
- **前提知識の 3 分類（2026-08-26 精緻化）:**
  - **A類（オントロジー外の必須数学）:** 円周角の定理・内接円/外接円・三角形の基本・座標距離など、中学数学以上でオントロジーに存在しないものは、**オントロジーへノード追加してから**教材で使う。追加 ID は既存の ID 規則に合わせる（例: JH-GEO-CIRCLE-ANGLE-01）。
  - **B類（オントロジー内・未作成）:** 未作成ノードが前提なら、その ID を `prerequisite_nodes` に書き、作成計画に載せる。教材該当ノードの前提表には「JSON正本（未作成）」と明記する。
  - **C類（日常・小学校層）:** 数直線・座席表・比例の感覚・分数の割り算など。`_refs/quick_references.md` に一行リファレンスを置き、ノード化しない。
- `trigonometry_master_ontology.md` は人間向けの全体地図。IDや依存関係が異なる場合はJSONを優先する。
- JSONにない前提を補う場合は `prerequisite_status: inferred` と明記し、量産前に確認する。
- 前提ノード、ノード外の基礎知識、現在ノード内のつまずきを分ける。
- 入口診断には「正答」と「理由の説明」の両方を求める。自己評価だけで理解済みとしない。

## 2. 学習者への入口

- 抽象的な定義や公式から始めず、単純な見方がどこで困るかを示す。
- サイズと比、単純足し算と正しい合成など、差が見える対比を使う。
- 小さな具体例を、導入・導出・点検まで途中で変えずに追わせる。
- 対象者が高校数学を前提にしなくても入れるよう、必要な用語だけ先に説明する。

## 3. 最小完全説明

各ノードは、次の順を基本にする。

1. 到達点を一文で示す
2. 必要な記号の読み方を示す
3. 図は説明量を減らす場合だけ原則1枚置く
4. 公式の意味と、定義・既知事実・今回の結論を区別する
5. 導出は各等号の理由を省略しない
6. 数値例または極端な場合で点検する
7. よくある誤りを示す
8. teach-backで自力説明を求める

短くする対象は重複や装飾であり、前提・理由・条件を削らない。

## 4. 読める表現

- Obsidianの数式ブロックは `$$ ... $$`、インライン式は `$ ... $` を使う。
- `θ`、`sin`、`cos`、`tan` など、読む必要のある記号には読み方を添える。
- 図の色・ラベル・本文・式を1対1に対応させる。
- SVGはタイトル、本文、主図、注釈の領域を分ける。注釈・公式パネルを図形に重ねない。
- フォントは日本語環境でのフォールバックを指定し、文字切れ・被りをレンダリング画像で確認する。
- **diagram のレイアウト検査**（パネルはみ出し・角度弧ずれ・注釈重なり）は [`_audit/DIAGRAM_LAYOUT_CHECK_v01.md`](./_audit/DIAGRAM_LAYOUT_CHECK_v01.md) に従う。新作・修正後は `python _audit/verify_svg_layout.py` を実行する。
- 学習者向け画面に、制作メタ情報や調査ログを混ぜない。

## 5. 理解度サポート

学習の流れは「学ぶ → やってみる → 例で定着 → 確認 → 教え返し」とする。

技能ごとに確認問題を置き、次の結果を区別する。

- **理解:** 正答でき、理由を見ずに説明できる
- **部分理解:** 正答できるが、理由または条件が説明できない
- **要復習:** 定義・操作・前提のいずれかを誤る

各確認問題には、失敗時に戻る本文の見出しまたは前提ノードを記載する。

## 6. 対話化の判断

静的教材の内容レビューとteach-backが終わってから判断する。

- **不要:** 静的な図と導出で関係を追える
- **有効:** 数値を動かすと不変量・符号・極限の理解が速くなる
- **有効性が高い:** 回転・軌跡・収束など、動きそのものが概念を構成する

動くこと、派手さ、操作数は完了条件ではない。

## 7. 完了ゲート

- [ ] JSONのノードID・前提・診断問題を照合した
- [ ] 本文を見ずに答えられる確認問題がある
- [ ] 公式の導出を各行の理由つきで再現できる
- [ ] 図・式・ラベル・読み方をObsidianで確認した
- [ ] SVGまたは画像を実際にレンダリングして視認性を確認した
- [ ] `verify_svg_layout.py` で diagram の L1–L3（パネル・弧・重なり）を確認した（手順: `_audit/DIAGRAM_LAYOUT_CHECK_v01.md`）
- [ ] 誤答時の復習先が決まっている
- [ ] teach-backで独立説明できる
- [ ] 上記を通過するまでインタラクティブ実装を完了扱いにしない
