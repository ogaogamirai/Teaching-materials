# 付録 A1：ZDDの内部データ構造と実社会での活用

## 0. なぜこの付録があるか（目的・意義・必然性）

### 意義——矢印の絵から、表（配列）へ

第7章までで、ZDD は `Node_e1` → `Node_e3` → SUCCESS のように **指で追える** ようになった。  
しかしコンピュータのメモリ上では、同じ情報は **整数3つずつの表（配列）** として持たれる。

> 実装やデバッグのとき、「箱の名前」だけでは足りない。  
> **表の何行目の、どの列を書き換えるか** まで対応づけたい——それがこの付録の役割です。

### 目的

1. 第7章の `Node_e*` と、表の **#1〜#4 行** を1対1で対応づける  
2. 上回り／下回りを、表上で **別世界線** としてコマ完走する  
3. 活用例を、第10章の袋の言葉（積・和・差）と接続する  

初めて読むときはスキップしてよい。第7章のあとに戻るとよい。

### 意味（必然性）——なぜ第7章の直後か

| 代替 | どこで足りないか |
|---|---|
| 第7章だけで終わる | 「Node_e3 とは何行目？」が言えない |
| いきなり実装コード | 表の各行が何を意味するか体験がない |
| **マップAの表をコマ送りで組み立てる** | 第7章の追跡と表の行き先が接続する |

| 第7章（本編） | この付録（発展的な理論補足） |
|---|---|
| `Node_e1` を指で追う | 表の **#1 行** |
| 0枝／1枝 | 2列目・3列目の整数（行き先ID） |
| 同じ SUCCESS | 終端 **1**（複数の箱から同じ成功へ——第4章§5の合体） |

---

## 0.5 言葉の確認

| マップ側 | ZDDデータ側 |
|---|---|
| 交差点 A, B, C, D | 表の行き先IDが指す「次の質問」 |
| 道路 $e_i$ | 各行の **担当道路**（質問のラベル） |
| 0 / 1 | 2列目・3列目の **行き先**（0=FAIL, 1=SUCCESS もここ） |

交差点そのものが表の1行になるわけではない。第6章の「交差点ノード」と混同しない。

## 1. マップA——第7章と同じ正本

![四角い町：上回り A→B→D ／ 下回り A→C→D](figures/ch06_town_map.svg)

成功ルート:

- **上回り**: $e_1=1,\ e_3=1$ → 第7章 `Node_e1(1) → Node_e3(1) → SUCCESS`
- **下回り**: $e_2=1,\ e_4=1$ → 第7章 `Node_e1(0) → Node_e2(1) → Node_e4(1) → SUCCESS`

### 第7章データとの対応表

| 第7章の箱 | 表の行 | 担当道路 |
|---|---|---|
| `Node_e1` | **#1** | $e_1$ |
| `Node_e2` | **#2** | $e_2$ |
| `Node_e3` | **#3** | $e_3$ |
| `Node_e4` | **#4** | $e_4$ |

> **重要**: 上回りは **#3 の 1枝で SUCCESS** に届く（#4 を経由しない）。  
> 旧版付録の「#3→#4 合体」は第7章正本と矛盾していたため、ここでは **第7章に揃える**。

## 2. 表の4行をコマ送りで立てる

第7章 §4 のデータを、表の形に写す。

### コマ1：`Node_e1` → **#1 行**

| 列 | 値 | よみ |
|---|---|---|
| 担当道路 | $e_1$ | 「イーワンを通るか？」 |
| 0の行き先 | **#2** | 通らない → 下回り側 |
| 1の行き先 | **#3** | 通る → 上回り側 |

**よみ**: 「#1 はイーワンの箱。ゼロ枝 #2、イチ枝 #3」

### コマ2：`Node_e2` → **#2 行**

| 列 | 値 | よみ |
|---|---|---|
| 担当道路 | $e_2$ | 「イーツーを通るか？」 |
| 0の行き先 | **0 (FAIL)** | 通らない → 失敗 |
| 1の行き先 | **#4** | 通る → イーフォーの箱へ |

### コマ3：`Node_e3` → **#3 行**

| 列 | 値 | よみ |
|---|---|---|
| 担当道路 | $e_3$ | 「イーサンを通るか？」 |
| 0の行き先 | **0 (FAIL)** | 通らない → 失敗 |
| 1の行き先 | **1 (SUCCESS)** | 通る → **ゴール（上回りはここで完走）** |

**よみ**: 「#3 のイチ枝は SUCCESS——第7章と同じ。上回りは #4 を聞かない」

### コマ4：`Node_e4` → **#4 行**

| 列 | 値 | よみ |
|---|---|---|
| 担当道路 | $e_4$ | 「イーフォーを通るか？」 |
| 0の行き先 | **0 (FAIL)** | 通らない → 失敗 |
| 1の行き先 | **1 (SUCCESS)** | 通る → ゴール（下回り） |

**よみ**: 「#4 は下回り専用の最後の質問。成功も終端 1——#3 と同じ SUCCESS」

### 完成表（第7章正本）

| ノードID | 担当道路 | 0 (通らない) | 1 (通る) |
|---|---|---|---|
| **#1** | $e_1$ | → #2 | → #3 |
| **#2** | $e_2$ | → FAIL (0) | → #4 |
| **#3** | $e_3$ | → FAIL (0) | → **SUCCESS (1)** |
| **#4** | $e_4$ | → FAIL (0) | → **SUCCESS (1)** |

**合体の正しい意味**: #2 と #3 が同じ行き先を指すのではない。  
**#3 と #4 の 1枝が同じ SUCCESS (1) を指す**——第4章§5の「同じ成功葉を共有」と同型。

## 3. 世界線：表の行き先を指で追う

> 読み方: 上回りだけ完走 → 下回りだけ完走。混ぜない。

### 世界線①：上回り

#### コマ1：#1 行——$e_1$ を通る

- **判定対象**: #1 行の 1の行き先  
- **判定方法**: 上回りなので **1** → 次は **#3**  
- **選択の根拠**: まず $e_1$  

**よみ**: 「#1(1) → #3 へ」

#### コマ2：#3 行——$e_3$ を通る

- **判定方法**: **1** → 行き先 **SUCCESS (1)**  

**よみ**: 「#3(1) → SUCCESS。上回り完走」

---

### 世界線②：下回り

#### コマ1：#1 行——$e_1$ を通らない

→ **0** → **#2**

**よみ**: 「#1(0) → #2 へ」

#### コマ2：#2 行——$e_2$ を通る

→ **1** → **#4**

**よみ**: 「#2(1) → #4 へ」

#### コマ3：#4 行——$e_4$ を通る

→ **1** → **SUCCESS (1)**

**よみ**: 「#4(1) → SUCCESS。下回り完走」

![付録 — 上回り・下回りの足跡](figures/chA1_footprints.svg)

第7章 §4 と **同じ足跡** である。

<details>
<summary>FAIL の一手（第7章と同型）</summary>

`#1(1) → #3(0) → FAIL`——上に行ったのに $e_3$ を使わない。
</details>

## 4. マップB——なぜ載せるか（第8章への橋）

マップAだけでは「同じ SUCCESS を共有」は小さく見える。  
第8章の合流マップでは、**前半が違うのに後半の `Node_e5` が1つ**——目で確認した。

| この付録で示すこと | 第8章で体験すること |
|---|---|
| マップBの樹形図 | 北／南が同じノート `[ M:1, A:0 ]` に合流 |
| 「同じ先は1回」 | `Node_e5` がデータ上 **1行に共有** |

![マップB — 前半は違う、後半を共有](figures/chA1_map_b.svg)

**よみ**: 「前半は違う。後半の質問ボックスだけ共有——第6章コマ6・第8章 §3–§5 でコマ完走済み。  
ここでは **表の行が1つにまとまる** イメージだけ押さえる」

## 5. 実社会での活用（誇張なし）

第10章の袋の言葉と接続する。万能の速度は約束しない。

### コントラスト例：避難ルートの一括削除

| 操作 | 袋の言葉 | 表への翻訳（イメージ） |
|---|---|---|
| 危険道路 OFF | 差集合 $A\setminus B$ | 危険側の枝を FAIL へ書き換え |
| 両方の避難所 | 積 $A\cap B$ | 両方 SUCCESS の枝だけ残す |

**よみ**: 「列挙せず、**行き先の整数を書き換える**——第12章の矢印手順が、表でも同じ」

### その他の代表例

- **インフラ**: 故障パターンの袋を持ち、和・積で残る構成を調べる  
- **配線**: 候補の集まりを ZDD で持ち、禁止条件を一括削除する

## 6. 理解チェック

**問題1**  
上回りを表で追う。`#1` から `#3` まで、0/1 を書け。

<details>
<summary>答え</summary>

#1 で 1 → #3。#3 で 1 → SUCCESS。`#1(1) → #3(1) → SUCCESS`。
</details>

**問題2**  
#3 と #4 の「1の行き先」が同じ SUCCESS である意味を、第4章§5の言葉で一文。

<details>
<summary>答え例</summary>

同じ成功結果を一つの終端に共有する——BDD入口の「同じ葉を合体」と同型。
</details>

**問題3**  
第12章の差演算は、表のどの列を書き換える操作に相当するか。

<details>
<summary>答え例</summary>

主に **1の行き先**（SUCCESS を FAIL に潰す）。数の引き算ではない。
</details>

## 7. 手を動かす課題

**[基礎]**  
下回りを `#1(0) → #2(1) → #4(1) → SUCCESS` と、表の行IDと 0/1 を声に出してなぞれ。

**[基礎]**  
`#1(1) → #3(0) → FAIL` を、第7章のどのコマ送り失敗例と同型か一言で。

**[発展]**  
第8章の `Node_e5` 共有を、「表の2行が同じ行き先IDを指す」と言い換えよ。

<details>
<summary>ユニークテーブル・変数順・Apply</summary>

実装では同じ `(担当道路, 0行き, 1行き)` の行を **ユニークテーブル** で1つにまとめる。  
変数順は $e_1,e_2,e_3,e_4$ 固定（第5章・第8章 §8）。  
Apply（第10〜12章）は、この表の行き先を再帰的に合成する手続きである。
