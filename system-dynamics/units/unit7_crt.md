# Unit 7 — 演習A（基本編）: CRTを作る — 現状問題ツリーで「本当の原因」を見つける

> **対象:** 中学2年生〜一般社会人
> **ゴール（L3 Teach-Back）:** 「個別対策では解決しない理由」と「根本原因（Root）に集中すると効率的に解決できる」ことを、自分の言葉で説明できる。CRTで根本原因を1つ特定できる
> **所要目安:** 20〜30分（例題つき）
> **準備:** 演習カード `exercises/ex1_getting_up.md`（例題）を手元に

---

## 1. Hook — まず「朝起きられない」を直してみよう（体験）

Aさんは朝起きられずに困っています。原因は「よく分からない」まま、いろいろ試してみました。

| 試した対策 | 結果 |
|---|---|
| 「朝ごはんを食べるようにした」 | 変わらない（そもそも食べる時間がない） |
| 「授業を楽しくしようと頑張った」 | 眠くなるのは変わらない |
| 「スマホをやめようとした」 | 1日は我慢できるけど、また戻る |
| 「疲れを取ろうと早く寝ようとした」 | なぜか夜更かししてしまう |

**全部、それっぽいのに、ぜんぜん解決しません。**

> **ここが大事な体験です。** 原因が分からないまま対策を打つと、症状を1個ずつ追いかける「モグラ叩き」になり、どれも根本からは直りません。

## 2. なぜ個別対策では解決しないのか（Value）

### 症状は「枝」で、原因は「根」にある

木を想像してください。枯れているのは**葉っぱ（症状）**ですが、問題の本当の場所は**根（根本原因）**にあります。

```
    葉っぱ（症状）: 朝起きられない・眠い・朝ごはんを食べられない・疲れてる…
       │
       │ （葉っぱを1枚ずつ直しても、根がダメならまた枯れる）
       ▼
     根（根本原因）: 夜更かし  ← ここを直すと、葉っぱがまとめて元気になる
```

- **個別対策** = 葉っぱを1枚ずつ治そうとする（モグラ叩き・非効率）
- **根本対策** = 根を1本直す（葉っぱがまとめて良くなる・効率的）

**この「根を見つけて、そこに集中する」ことが、合理的で効率的な解決の第一歩です。**

### CRTの意義（このUnitの核心）

> **「原因が分かりにくい状態」から、因果関係でつなぎ合わせることで「根（Root）」を1つに絞り込む。それがCRT（現状問題ツリー）を作る意義です。**

- CRTを作る前: 原因がいくつもあるように見えて、何を直せばいいか分からない
- CRTを作った後: **Root（根本原因）が1つに見える**。直す場所が決まる

## 3. CRTとは（Purpose→Meaning）

### Purpose（目的）
問題（UDE）を因果関係でつないだ「木のような図」を作り、**Root（根本原因）を1つに絞り込む**。

### Meaning（意味）

| 用語 | 意味 |
|---|---|
| **UDE**（Undesirable Effect） | 現状の不都合な事象（症状・観測できる問題） |
| **Cause（原因ノード）** | UDEの背後にある原因。観測できる症状ではないが、「なぜUDEが起きるか」を説明するノード |
| **CRT**（Current Reality Tree） | 現状問題ツリー。UDEとCauseを「なぜなら」でつないだ図 |
| **Core Constraint / Root** | 根本原因。矢印が一番多く「原因」として出ているノード |

### CRTには2種類のノードがある

CRTは、**UDE（症状）と Cause（原因）の2種類のノード**でできています。

```
[UDE] 観測できる症状（朝起きられない・眠い・疲れてる）
  ↑ 「なぜなら」
[Cause] その原因（睡眠不足・夜更かし・スマホ）← 症状ではないが、原因としてある
  ↑ 「なぜなら」
[Root] 根本原因（夜更かし）← 矢印が一番出ている
```

- **Step1**では「観測できる症状」から始める（**起点はUDE**）
- **Step2**で原因を掘り下げると、**UDEではない Cause** が次々と現れる（スマホ・睡眠不足・習慣など）
- 掘り下げの果てに **Root（根本原因）** へ到達する

> **大切なこと:** CRTは「症状（UDE）だけの図」ではありません。**症状から出発して、原因（Cause）を掘り下げ、Rootに至るまでの全体図**です。Step1で「原因は書かない」と言うのは、**最初の出発点を症状に揃えるため**であって、原因ノードを書いてはいけない、という意味ではありません。

## 4. CRTの作り方（4ステップ）

```
Step1 問題（UDE）を列挙する
   ↓ 出発点。「観測できる症状」を1項目1文で書き出す
Step2 因果でつなぐ・原因を掘り下げる
   ↓ 「Aが起きる、なぜならBだから」の矢印で結ぶ
   ↓ 症状の背後にある Cause（原因ノード）も追加していく
Step3 輪（ループ）を探す
   ↓ 悪循環（負のループ）があれば、それが「現状が続く理由」
Step4 Root（根本原因）を特定する
   ↓ 「原因」として矢印が一番多く出ているノードが Core Constraint
```

> **補足:** ノードのラベル（UDE / Cause / Root）は、CRTの中で**相対的**です。あるノードは、上から見れば「原因（Cause）」、下のノードから見れば「結果」です。ラベル分けは、**どこが観測できる症状（UDE）で、どこが内部の原因（Cause）か**を区別するための目印として使います。

## 5. 例題（EX1: 朝起きられない）— Rootが見える体験をしよう

「原因が分からない」状態から、CRTを作って Root を1つに絞る体験を追います。

### Step1: 出発点は、観測できる症状（UDE）から

CRTは「観測できる症状」から始める。原因はまだ探さない。まずはっきり見えている症状だけを書く。

> ここがポイント。Aさんの問題は「朝起きられない」だけではありません。**一見バラバラに見える複数の症状**があります。

| # | UDE（観測できる症状） |
|---|---|
| UDE1 | 朝、起きられない |
| UDE2 | 朝ごはんを食べない |
| UDE3 | 授業中に眠くなる |
| UDE4 | 成績が下がった |
| UDE5 | イライラして友達と衝突する |

「朝起きられない」「成績が下がる」「友達と衝突する」…全部別々の問題に見えます。これを1本のツリーにしていきます。

### Step2: 「なぜなら」でつなぎ、原因（Cause）を掘り下げる

「Aが起きるのは、なぜならBだから」の矢印で、それぞれの症状の原因を掘り下げていく。

```
[UDE: 朝、起きられない]
   │ なぜなら（寝るのが遅い）
   ▼
[UDE: 朝ごはんを食べない]
   │ なぜなら（起きるのが遅くて時間がない）
   ▼
[Cause: 午前中のエネルギー不足]
```

```
[UDE: 授業中に眠くなる]
   │ なぜなら
   ▼
[Cause: 集中力が続かない]
   │ なぜなら
   ▼
[UDE: 成績が下がる]
```

```
[UDE: イライラする]
   │ なぜなら
   ▼
[UDE: 友達と衝突する]
```

ここまでで、**「朝の症状」「授業・成績の症状」「気分・人間関係の症状」の3つの枝**ができました。一見、全く別々の問題です。

### Step3: 3つの枝が「共通の原因」に合流する

ここからがCRTの見せどころ。それぞれの枝をさらに上に辿ると…

> 「午前中のエネルギー不足」はなぜ？ → **睡眠不足（Cause）**
> 「集中力が続かない」はなぜ？ → **睡眠不足（Cause）**
> 「イライラする」はなぜ？ → **睡眠不足（Cause）**

**3つの別々に見えた症状が、全部「睡眠不足」という1つの共通原因に合流します。**

```
[Cause: 午前中のエネルギー不足] ─┐
[Cause: 集中力が続かない] ────────┼──► [Cause: 睡眠不足]
[UDE: イライラする] ──────────────┘
```

そして「睡眠不足」はなぜ？ → **夜更かし（Cause）**。夜更かしはなぜ？ → **寝る前にスマホを見てしまう（Cause）**。

### Step4: Root（根本原因）を特定する

全体のツリーはこうなります。

```
[UDE: 朝、起きられない]
   ▼
[UDE: 朝ごはんを食べない]
   ▼
[Cause: 午前中のエネルギー不足] ─┐
                                ├─► [Cause: 睡眠不足] ◀── [Cause: 夜更かし] ◀── [Cause: 寝る前にスマホ] ← Root
[UDE: 授業中に眠くなる] ─────────┘
   ▼
[Cause: 集中力が続かない]
   ▼
[UDE: 成績が下がる]

[UDE: イライラする] ──► [UDE: 友達と衝突する] ──►（ここも睡眠不足に合流）
```

- 「朝起きられない」「成績が下がる」「友達と衝突する」… **見た目はバラバラの5つの症状**
- でも因果を辿ると、**全部が「睡眠不足」→「夜更かし」→「スマホ」という1本の Root に集まる**

> **Root（根本原因）= 夜更かし（寝る前にスマホを見てしまう）**

### ここで何が変わったか（体験のまとめ）

- CRTを作る前: 「朝起きる努力をしよう」「勉強を頑張ろう」「友達と仲直りしよう」と、**5つの対策**がバラバラに浮かぶ（モグラ叩き）
- CRTを作った後: **「夜更かし」を直せば、5つの症状がまとめて改善し始める**と分かる

**これがCRTの良さです。** 「散らばった問題（UDE）」を因果でつないでいくと、「実は1つの根本原因（Root）で説明できる」という収束が見えてきます。Rootを直すことで、複数の症状をまとめて改善できます。これは、個別にモグラ叩きするよりはるかに効率的です。

> **ここまでがCRTの意義。** 次は Root（夜更かし）をどう解消するか（Unit 8 で）。

## 6. 演習フレーム（Unit 7〜9 共通）

各演習カードは次の共通フレームで進める。このUnitでは **Step1〜4（CRTまで）**。

```
Step1 題材を選ぶ（選択式）
Step2 問題（UDE）を列挙する
Step3 因果でつなぐ（CRT / ループ図）
Step4 Root（根本原因）を特定する
Step5 対立を解体する（蒸発する雲）※Unit 8
Step6 解消策（Injection）を設計する ※Unit 8
Step7 新たな問題が起きないか確認する（FRT）※Unit 8
Step8 Teach-Back（自分の選んだ題材で説明）
```

## 7. Check — 確かめてみよう

1. 「個別対策（モグラ叩き）」がうまくいかない理由は？（ヒント: 葉っぱと根）
2. CRTを作ると、何が「見える」ようになる？
3. Root（根本原因）は、図のどこを見れば分かる？
4. 例題の「朝起きられない・成績が下がる・友達と衝突する」は、見た目は別々の問題。でもCRTで辿ると何が分かる？
5. 「朝起きられない」は UDE（症状）と Cause（原因）のどちら？ では「夜更かし」は？

> **答え（下を見る前に自分で）:**
> 1. 症状（葉っぱ）を1個ずつ直しても、根本原因（根）がダメならまた戻るから
> 2. 根本原因（Root）が1つに絞られて、直す場所が決まる
> 3. 「原因」として矢印が一番多く出ているノード（＝最も下流にあり、複数の枝が合流するところ）
> 4. 全部が「睡眠不足」→「夜更かし」という1つの Root に収束すること
> 5. 「朝起きられない」は UDE（観測できる症状）。「夜更かし」は Cause（原因ノード。さらに Root）

## 8. よくある誤解（Misconceptions）

| 誤解 | 正しい理解 |
|---|---|
| 「原因が分からなくても、とにかく何か対策すればいい」 | 原因が分からない対策はモグラ叩き。まず構造を見る（CRT）のが先 |
| 「原因を全部直すのが良い」 | 根本原因1つを直すと複数の症状がまとめて良くなる。全部直すのは非効率 |
| 「解決策から考えてOK」 | 先に「原因（構造）」を特定する。解決策（Injection）は Unit 8 |
| 「原因と症状が混ざってOK」 | 混ざってよいが**区別**はする。Step1の出発点は「観測できる症状（UDE）」。原因ノード（Cause）はStep2で掘り下げて追加する。区別を意識しないと、Rootが見えなくなる |

## 10. Teach-Back — 素人に説明しよう

1. **何の話か:** 「バラバラに見える問題は、実は1つの根本原因（根）から出ている」という話
2. **部品は何か:** UDE（症状）・Cause（原因）・矢印（因果）・Root（根本原因）
3. **どう繋がるか:** 症状を「なぜなら」で辿ると、複数の枝が1つの Root に合流する
4. **図はどこを見ればいいか:** 複数の枝が合流して、矢印が一番「原因」として出ているノード
5. **よくある誤解:** 個別対策（モグラ叩き）は解決しない。Rootに集中する
6. **素人への一言:** 「朝起きられない・成績が下がる・友達と衝突する…全部別の問題に見えるけど、辿ると全部『夜更かし』に集まるんだよ。根っこを1本直せば、枝の症状がまとめて良くなる」

## まとめ（Takeaway）

- 原因が分からないままの対策は**モグラ叩き**。症状（葉っぱ）を直しても、根（Root）がダメなら戻る
- **CRT** = 症状（UDE）を出発点に、原因（Cause）を掘り下げ、「なぜなら」でつないで **Root（根本原因）を1つに絞り込む**道具
- CRTには **UDE（症状）と Cause（原因）の2種類のノード**がある。出発点は UDE、掘り下げで Cause を追加
- CRTの醍醐味は**収束**: バラバラに見える複数の UDE が、因果を辿ると1つの Root に合流するのが見えること
- **Rootに集中する**と、複数の症状がまとめて改善する。これが合理的で効率的な解決
- 次回は Root（根本原因）をどう解消するか（蒸発する雲・Injection）

> **次回予告 (Unit 8):** 見つけた Root を、対立の解体で「根本から解消」する。
