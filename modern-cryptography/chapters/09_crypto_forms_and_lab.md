# 10　暗号は実際にどんな形になるか

## この章の目的

これまで学んだ方式を、実際の入力から出力を作って確かめます。

大切なのは、暗号方式によって「暗号文の見た目」も「秘密の置き場所」も違うことです。

[個別モデル：暗号化ラボ（シフト・XOR・RSA・SHA-256・AES）](../models/crypto_lab.html)

```text
方式       入力              出力の例             秘密の中心
シフト     文字              ずれた文字列         ずらす数
XOR        数字の列          別の数字の列         共通鍵
RSA        数字              大きな数字           秘密指数
ハッシュ   文章・ファイル    固定長の指紋         復号鍵はない
ECC        点・整数          公開点・署名         秘密の整数
AES        データ            バイト列             共通鍵
```

## 1. シフト暗号：文字がずれる

### やってみる

アルファベットを数字にして、3つずらします。

```text
A=0, B=1, ..., Z=25
```

`CAT` は、

```text
C → F
A → D
T → W
```

となり、暗号文は `FDW` です。復号では3つ戻します。

これは暗号の考え方を体験する模型です。文字の並びを試せばすぐ破れるため、現代の安全な暗号ではありません。

### 教え返し

> シフト暗号では、アルゴリズムは公開しても、ずらす数を秘密にします。しかし候補が少ないため、全部試せば破れます。

## 2. XOR：同じ鍵で閉じて開ける

### XORとは何か

XORは、2つのビットが異なるとき1、同じとき0になる計算です。

```text
0 XOR 0 = 0
0 XOR 1 = 1
1 XOR 0 = 1
1 XOR 1 = 0
```

同じ鍵をもう一度使うと元に戻ります。

```text
データ XOR 鍵 = 暗号文
暗号文 XOR 鍵 = データ
```

### 形を見てみる

```text
データ   10110010
鍵       01100101
暗号文   11010111
```

```text
暗号文   11010111
鍵       01100101
元データ 10110010
```

XORは共通鍵暗号の考え方を見せるのに便利ですが、同じ鍵を繰り返し使うだけでは安全な暗号になりません。

## 3. RSA：数字の暗号文と公開鍵

chapter 03の小さなRSAを使います。

```text
p=5, q=11
n=55
公開鍵=(n,e)=(55,3)
秘密鍵=d=27
```

メッセージ `m=7` を暗号化すると、

$$
c\equiv7^3\equiv13\pmod {55}
$$

暗号文は数字 `13` です。受信者は秘密指数 `27` で、

$$
13^{27}\equiv7\pmod {55}
$$

として元に戻します。

ここで見せたいのは、RSAの暗号文が「読めない文字」ではなく、公開鍵で計算された数になることです。実用RSAでは桁数も方式も異なり、この小例を安全な通信に使ってはいけません。

## 4. ハッシュ：暗号文ではなく指紋

`hello` のSHA-256ハッシュは、入力の長さに関係なく256ビットの値になります。少しでも入力を変えると、出力全体が大きく変わります。

```text
入力       hello
出力       固定長の16進数列
```

ハッシュには復号がありません。入力を隠すためではなく、ファイルやメッセージが変わっていないかを確認するために使います。

## 5. ECC：暗号文ではなく、公開点と秘密の計算

ECC（*Elliptic Curve Cryptography*：楕円曲線暗号）は、RSAのように文章を直接「楕円曲線の暗号文」へ変える方式ではありません。

```text
公開：曲線、基準点G、公開点kG
秘密：整数k
```

`kG` は公開しても、`G` と `kG` から `k` を戻すのが難しい、という構造を使います。

### ECDHで通信する

ECDH（*Elliptic Curve Diffie–Hellman*）では、2人がそれぞれ秘密の整数を選び、公開点を交換します。公開点から同じ共通秘密を作り、その共通秘密をAESの鍵へ変換します。

```text
ECC / ECDH：共通鍵を作る
AES        ：本文を暗号化する
```

## 6. AES：実際のデータをバイト列にする

AES（*Advanced Encryption Standard*：高度暗号化標準）は、共通鍵を使ってデータを暗号化します。

```text
平文：Hello
  ↓ AES + 共通鍵
暗号文：読めないバイト列
```

AESの内部は、バイトの置換・並べ替え・有限体の計算を何度も組み合わせています。ここでは手作りのAESを作るのではなく、有限体が実際の暗号部品に使われることを確認します。

## 実演コーナーのルール

実際に操作するラボでは、各方式に次の4欄を置きます。

1. 入力
2. 秘密にするもの
3. 暗号化・変換後の出力
4. 復号または検証ができるか

### 方式ごとの注意

- シフト暗号・小さなRSA・単純XORは、理論を学ぶための模型。
- ハッシュは変換できるが、復号する方式ではない。
- ECCは、鍵交換や署名のための数学的部品。
- AESは、実データを守る共通鍵暗号。
- 実用上の鍵生成・乱数・パディング・認証を省いた小例は、安全な通信に使えない。

## Teach-back

**課題**：RSA、ECC、AESの出力の違いを説明してください。

**模範回答**：

> RSAでは、数字を公開鍵で計算した数字が暗号文になります。ECCでは、文章を直接暗号化するのではなく、公開点と秘密の整数の関係を使って共通鍵や署名を作ります。AESでは、共通鍵を使って文章やファイルを読めないバイト列へ変えます。

**課題**：ハッシュが暗号文でない理由を説明してください。

**模範回答**：

> 暗号文は正しい鍵で元の文章へ戻しますが、ハッシュ値には復号鍵がありません。ハッシュは内容を隠すよりも、同じ内容か、途中で変わっていないかを確かめるための短い指紋です。
