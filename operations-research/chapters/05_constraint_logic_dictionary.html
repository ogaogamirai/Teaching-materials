① 「1人1日1シフト」の絶対原則（排他） 基本中の基本

人間の言葉：「同じ日に日勤と夜勤を両方やったり、出勤なのに休みになったりするのは物理的にあり得ない！」

💡 数学的判定式（音読）： 日勤フラグ ＋ 夜勤フラグ ＋ 休日フラグ ＝ ちょうど1
$$x_{s, d, \text{D}} + x_{s, d, \text{N}} + x_{s, d, \text{O}} = 1$$
# CP-SATなら専用メソッドで一撃（内部でCDCLが超高速に排他伝播） for s in staff: for d in days: model.AddExactlyOne([x[s, d, shift] for shift in ["D", "N", "O"]])
② 「毎日の必要人数の確保」（縦の合計） 現場の維持

人間の言葉：「毎日必ず、日勤に1人、夜勤に1人は現場にいなければ仕事が回らない！」

💡 数学的判定式（音読）： 全スタッフの日勤フラグを足し合わせた合計が 1 に等しい
$$\sum_{s \in \text{Staff}} x_{s, d, \text{D}} = 1, \quad \sum_{s \in \text{Staff}} x_{s, d, \text{N}} = 1$$
for d in days: model.Add(sum(x[s, d, "D"] for s in staff) == 1) model.Add(sum(x[s, d, "N"] for s in staff) == 1)
③ 「夜勤の翌日は日勤禁止」（隣接インターバル規制） 健康・労働衛生

人間の言葉：「朝まで夜勤をやった数時間後に、そのまま日勤に入るのは過労死ラインだから絶対NG！」

💡 数学的判定式（音読）： 「今日夜勤(1)」かつ「明日日勤(1)」の同時成立を禁止（足して1以下）
$$x_{s, d, \text{N}} + x_{s, d+1, \text{D}} \le 1$$
for s in staff: for d in range(len(days) - 1): model.Add(x[s, days[d], "N"] + x[s, days[d+1], "D"] <= 1)
🌟 ④ 「どのスタッフも、一週間に2連休を最低1回取らせる」（連休制約） 超頻出・応用パズル

人間の言葉：「飛び石連休ばかりだと旅行にも行けず疲れが取れない。一週間のうち必ずどこかで『2日連続の休み』を取らせて！」

💡 思考のステップ（補助変数 ＋ AND ＋ OR）：
1. 2連休になり得るペアは、週に6箇所（月火, 火水, 水木, 木金, 金土, 土日）。
2. 各ペアについて「両日休みか？」を表すスイッチ（補助ブール変数 $c_{s, d}$）を作る。
3. $c_{s, d} \iff (x_{s, d, \text{O}} \land x_{s, d+1, \text{O}})$ （両日休みならスイッチON）
4. 全6ペアのうち「少なくともどれか1つがON」： $\sum_{d=0}^{5} c_{s, d} \ge 1$
for s in staff: two_off_pairs = [] for d in range(len(days) - 1): # 補助変数: このペアが2連休か？ pair_flag = model.NewBoolVar(f"two_off_{s}_{days[d]}_{days[d+1]}") # pair_flag が 1 になるのは「今日が休み」かつ「翌日も休み」のとき model.AddBoolAnd([x[s, days[d], "O"], x[s, days[d+1], "O"]]).OnlyEnforceIf(pair_flag) two_off_pairs.append(pair_flag) # 6つのペアのうち、最低1回は成立していなければならない！ model.Add(sum(two_off_pairs) >= 1) # または model.AddBoolOr(two_off_pairs)
⑤ 「3連勤以上は禁止」（連続勤務の上限） 過労防止

人間の言葉：「3日連続で勤務（日勤または夜勤）させるな！ 3日間の窓の中に最低1日は休みを入れろ！」

💡 数学的判定式（音読）： 任意の連続する3日間において、休みの合計が 1日以上
$$x_{s, d, \text{O}} + x_{s, d+1, \text{O}} + x_{s, d+2, \text{O}} \ge 1 \quad (\forall d)$$
for s in staff: for d in range(len(days) - 2): model.Add(x[s, days[d], "O"] + x[s, days[d+1], "O"] + x[s, days[d+2], "O"] >= 1)
⑥ 「個人の希望休・わがまま」（ソフト制約 ＝ ペナルティ化） 柔軟な最適化

人間の言葉：「Aliceは水曜日に休みたい。どうしても無理なら仕方ないけど、できる限り叶えて！」

💡 数学的判定式（音読）： 叶わなかった時（$x=0$）にペナルティ加算、叶えば（$x=1$）ペナルティ0
$$\text{Penalty} = \text{Cost} \times (1 - x_{s, d, \text{O}})$$
penalties = [] # Aliceの水曜休み希望（叶わなければ +10点 の不満ペナルティ） penalties.append(10 * (1 - x["Alice", "水", "O"])) # ソルバーに「不満の合計を最小にせよ！」と命じる（MaxSAT二分探索が始動） model.Minimize(sum(penalties))

🎓 第5章の重要チェックポイント（制約構築の黄金律）

  • ExactlyOne: 排他選択は AddExactlyOne([x, y, z]) または sum(...) == 1。
  • 時間軸スライス（スライディングウィンドウ）: 「2連休」や「最大3連勤」は、連続する日付ブロックをループで回して不等式を立てる。
  • ハード制約とソフト制約の境界: 破綻させないための絶対制約は Add(...)、妥協を許す希望は次章（第6章）の「ペナルティ（目的関数）」へ回す。
