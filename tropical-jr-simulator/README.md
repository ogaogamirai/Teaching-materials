# 東京都内JRネットワーク × トロピカル代数 最短＆最長（一筆書き大回り）シミュレーター

東京都内のJR主要路線（87駅・200有向区間）の公開データを元に、**トロピカル線形代数（Min-Plus半環上の行列積）**を用いて任意の2駅間の最短所要時間・営業キロを算出すると同時に、乗り鉄の醍醐味である**「一筆書き大回り乗車（単純最長経路探索）」**を体感できる自己完結型Webシミュレーターです。

---

## 🌟 特徴

1. **完全自己完結型（Zero Dependency）**:
   - 外部サーバー、APIキー、バックエンド通信は一切不要。
   - `index.html` をブラウザ（Chrome, Edge, Firefox, Safari等）でダブルクリックするだけで即座に稼働します。
   - GitHub Pages 等にそのままデプロイして一般公開可能。
2. **トロピカル行列演算（Min-Plus半環）による決定論的解法（P: 多項式時間）**:
   - グラフ探索（ダイクストラ法等）を、トロピカル半環上の「行列の掛け算（$A \otimes A$）」として解く美しさを体感できます。
   - 全対間最短経路を一瞬で算出。
3. **乗り鉄のロマン「一筆書き大回り乗車」エンジン搭載（NP困難）**:
   - JR東日本の「大都市近郊区間内相互発着の特例（旅客営業規則第157条第2項）」を再現。
   - 「同じ駅を2度通らない（一筆書き）」という制約のもと、隣り合う駅同士（例: 東京➔神田、品川➔田町）でも都内を何十キロも巡る長大な大回りルートを探索・可視化。
   - 最短営業キロとの倍率（例: 「最短の35倍の長旅！」）も自動計算。
4. **数理と計算複雑性のダブル可視化**:
   - なぜ最短経路は行列積で一瞬で解けるのに、一筆書き最長経路はNP困難の難問になるのか？（Max-Plus半環の無限閉路問題）を体感するインスペクターを搭載。

## 🚀 使い方

1. `index.html` をブラウザで開きます。
2. **「出発駅」** と **「到着駅」** をプルダウンから選択（または「おすすめ区間クイック選択」をクリック）。
   - 特に「東京 ➔ 神田」や「品川 ➔ 田町」などの隣接駅を選ぶと大回りの効果が際立ちます！
3. **経路探索モード**を選択：
   - ⏱️ **最短時間** / 📏 **最短距離**（トロピカル代数・多項式時間）
   - 🚃 **最長距離（大回り）** / ⏳ **最長時間（大回り）**（一筆書き探索・NP困難）
4. 即座に経路、所要時間、営業キロ、経由駅のステップ、および数理インスペクターが表示されます。

## 📐 トロピカル代数（Min-Plus代数）のルール

| 演算 | 記号 | 意味・定義 |
|---|:---:|---|
| **加算** | $a \oplus b$ | $\min(a, b)$ （短い・速い方を選ぶ） |
| **乗算** | $a \otimes b$ | $a + b$ （所要時間や距離を足し合わせる） |
| **零元** | $\varepsilon$ | $+\infty$ （線路が繋がっていない） |
| **単位元** | $e$ | $0$ （その場に留まるコストはゼロ） |

### トロピカル行列積による最短経路
駅数を $N$、隣接行列を $A$ とすると、中継駅 $k$ を経由するトロピカル行列積は：
$$
(A \otimes B)_{ij} = \bigoplus_{k=1}^N (A_{ik} \otimes B_{kj}) = \min_{1 \le k \le N} (A_{ik} + B_{kj})
$$
となり、**行列の掛け算そのものが「最短経路の探索」と完全に一致**します。

## 🌲 ZDD（フロンティア法）による一筆書き全数圧縮と厳密解

JR都内ネットワーク（無向98エッジ）において、エッジのON/OFF全通りは $2^{98} \approx 10^{29}$ 通り（天文学的爆発）となります。  
しかし、日本発の世界的アルゴリズムである**フロンティア法（Simpath）**を用いると、境界線上の未決定端点（フロンティア）のみを管理することで、**最大フロンティア幅をわずか12頂点（平均5.69頂点）に抑え込み**、全解空間をコンパクトなDAG（有向非巡回グラフ）へと超圧縮できます。

一度ZDDが構築されれば、DAG上の動的計画法（DP）により、**真の最長ルート（厳密最適解）が一瞬で特定**できます。
