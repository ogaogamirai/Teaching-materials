# math-nodes

42ノード仕様書に対応する、ノード単位の静的教材置き場。

**GitHub 閉じ役:** **J.T.**（実装は J.T. / Nova 並行可）— [`GITHUB_CLOSER_ROLES_v01.md`](../../../Tools/GITHUB_CLOSER_ROLES_v01.md)

## 方針

- まず本文と導出を完成させる。インタラクティブ化は後段で判断する。
- 1ノード1ディレクトリ。本文の正本は `lesson.md`。
- 図は、説明を短くする効果がある場合だけ原則1枚まで置く。
- 公式は「何を意味するか」「どの前提から出るか」「各変形の理由」を分けて書く。
- 本文を正本、図を対応表現、インタラクティブ部品を後段の操作盤として分ける。
- 抽象的な定義から始めず、失敗する見方と役に立つ見方を対比し、小さな具体例を最後まで追う。
- 学習の流れは「学ぶ → やってみる → 例で定着 → 確認 → 教え返し」にする。
- 数式は見えるだけでなく読めるようにし、必要な記号の読み方を本文の冒頭に置く。
- 理解度は自己申告だけで決めず、技能ごとの短い問いと「理由を説明できるか」で判定する。
- 各ノードに `prerequisite_nodes` と入口判定を置き、依存関係の事実と本文からの推定を区別する。
- 最後に、学習者が自分の言葉で再現できる確認項目を置く。

## 1ノードの構成

```text
math-nodes/
  <NODE-ID>/
    lesson.md
    diagram.svg       # 必要な場合だけ
```

テンプレートは `_TEMPLATE.md`。本文を作る前に、ノードID・前提・到達点を埋める。

作成時の詳細基準は [`AUTHORING_STANDARD.md`](./AUTHORING_STANDARD.md)。diagram ありのノードは [`_audit/DIAGRAM_LAYOUT_CHECK_v01.md`](./_audit/DIAGRAM_LAYOUT_CHECK_v01.md) の検査手順も通す。次のノードはこの基準で内容レビューを通してから作成する。

## 依存関係の正本

- 機械的なノードID・`prerequisites`・`diagnostic_query` は、プロジェクト内スナップショット `math-nodes/ontology/math_euler_complete_ontology.json` を正本として教材から参照する。原本は `G:/マイドライブ/Eleanor Arroway/documents/math_euler_complete_ontology.json`。
- `G:/マイドライブ/Eleanor Arroway/documents/trigonometry_master_ontology.md` はMermaidと人間向けの全体地図として参照する。
- JSONに記載がある前提は推測せず転記し、`prerequisite_status: source_confirmed` とする。
- JSONにない前提を本文から補う場合は `inferred` と明記し、量産前に確認する。
- 2資料でIDが異なる場合は、別名表を整備するまでJSONのIDを教材の正規IDとして使う。

## 内容の合格ゲート

1. 主張を一文で言える
2. 記号と前提を説明できる
3. 公式を各等号の理由つきで導出できる
4. 図の各線分と式の各項を対応づけられる
5. 数値または極端な場合で結果を点検できる
6. よくある取り違えを自分で退けられる
7. 「やってみる」を確認テストの前に経験している
8. 教材を閉じた後に、短い teach-back を実行できる
9. 誤答時に戻るべき本文の場所が分かる
10. 前提ノードの入口判定と、ノード内の復習先が分離されている

## Captain レビューチェックリスト（Obsidian・Reading View）

各ノードを Obsidian で開いたとき、以下の 3 観点だけ順に見ると 1 ノード 2〜3 分で確認できる。

**1. 数式（KaTeX）**
- [ ] `$$ ... $$` と `$ ... $` が数式として表示されている（生の TeX 文字列が残っていない）
- [ ] インライン `$` の閉じ忘れで段落全体が崩れていない
- [ ] `\frac` などの二重バックスラッシュ（`\\frac`）によるエラーがない

**2. SVG 図**
- [ ] `diagram.svg` が読み込み表示されている（画像リンク切れでない）
- [ ] ラベルの重なり・文字切れ・端の見切れがない
- [ ] 右側のパネル領域と本文要素の干渉がない

**3. callout・details**
- [ ] `> [!abstract] 核心`・`> [!success] 合格ライン`・`> [!question] まずやってみる`・`> [!tip]` ・`> [!warning]`・`> [!note]` がカード表示されている
- [ ] `<details>`（答えを確認する）がクリックで展開できる

**承認の記録:** 確認済みノードは、このページ下部の進捗表で `✅` に更新し、`lesson.md` の frontmatter `status:` を `draft` → `approved` に書き換える（例: `HS1-TRIG-DEF-01`）。

## Obsidianでの表示基準

- 数式ブロックは `$$ ... $$`、インライン式は `$ ... $` を使う。
- 本文は Reading View で確認し、数式が生のTeX文字列になっていないことを合格条件にする。
- 図は本文と同じノードディレクトリに置き、相対リンクで表示する。
- 要点・注意・想起問題は Obsidian Callout で区別し、長い説明を一つの段落に詰め込まない。
- 表示できることを、単なる閲覧上の都合ではなく、式・図・記憶フックを対応づける学習条件として扱う。
- 主要記号の読み方が本文または数式の近くにあることを、表示確認の合格条件にする。

## インタラクティブ化の判断

静的教材のレビュー後、次のいずれかに分類する。

- **不要:** 図と導出だけで関係が追える
- **有効:** 数値を動かすと不変量・符号・極限などの理解が速くなる
- **必須に近い:** 動きや操作そのものが概念（回転、収束、軌跡）を構成する

動くこと自体は合格条件にしない。
