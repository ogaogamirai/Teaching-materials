左右図：錠とRSA

暗証番号の錠（公開ルールなし）

手元にあるのは錠だけです。公開された数式も公開鍵もありません。できるのは、番号を一つ入力して「開いた／開かない」を聞くことだけです。

00 を入力 → 開かない
01 を入力 → 開かない
…（外の錠が Yes/No を返す）

量子では解けない：重ね合わせの番号を普通の錠へ送れません。結果を読むと測定になり、一つの番号に壊れます。検査を自分の回路として書けないので、Oracleが組めません。

小さなRSA（公開鍵とルールあり）

手元にあるのは公開鍵 (n,e)=(55,3)、暗号化ルール、暗号文 C=13 です。秘密のメッセージ 7 や秘密鍵は不要です。

check(x) = (x³ mod 55 == 13)

量子回路が組める：この検査は公開情報だけで自分のゲートにできます。候補を探すこの手順の名前はグローバーです。暗号文 13 だけ、あるいは暗証の錠だけ、では組めたことになりません。

ありがたみ：公開鍵暗号は「秘密を隠したまま、検査の数式を公開する」設計です。その公開数式があるから、答えを知らなくても Oracle が作れます。暗証の錠は検査の数式を公開しないので、量子の土台がありません。

本編骨格Cのグローバーです。候補はメッセージ 5, 6, 7, 8。当たりは 7。ショアの周期探しではありません。用語の定義は本編を正本とします。

ψ（プサイ）：式の |ψ⟩ は、いまの量子状態全体の名前です。

  1. 準備：4候補を均等に含む状態を作ります。これは、まだ答えを知った状態ではありません。
  2. 印付け：当たりの候補だけ、振幅の「向き」を反転します。確率はまだ変わりません。
  3. 干渉：波の向きを足し合わせ、不正解を打ち消し、正解を強めます。
  4. 測定：最後に一つだけ読み出します。読み出す前に、正解が出やすい状態を作っておくことがポイントです。

比喩と正確さ：「波」は理解の入口の比喩です。正確には、量子状態の振幅を計算し、その絶対値の二乗を測定確率として読みます。

何を測る？回路の最後の量子状態を、メッセージ 5, 6, 7, 8 のどれとして読み出せるかを測ります。候補が出る確率は、その振幅を2乗した値です。測定すると量子状態は、その一つの結果に確定します。

グラフは量子状態そのものではなく、測定して得た候補の回数です。一回なら一つの結果だけ、繰り返せば結果の分布が表れます。

四つの確認点

  1. Oracle：「正解かどうか」を判定する問題の機能です。答えを表示する機械ではなく、判定結果を量子状態へ反映します。
  2. 印付け直後：正解の振幅の符号だけが変わるため、振幅の二乗である確率はまだ変わりません。
  3. 干渉：平均を基準に振幅を混ぜる操作です。正解と不正解の向きの違いが、確率の違いへ変換されます。
  4. 測定：一回の測定は一つの結果です。上の実験で同じ回路を20回繰り返すと、初めて結果の分布を観察できます。

測定結果をどう解釈するか

  1. 一回の測定：候補を一つ得ます。ただし、その一回だけで「必ず正解」とは限りません。
  2. 検証：得られた候補を、問題の判定条件 check(x) に普通の計算で入れ、Yesになるか確かめます。
  3. 繰り返し：同じ回路を何度も実行し、ヒストグラムを作ります。理想的に正解が一つで、正解の確率が十分高ければ、最も多く出た候補を有力な答えと解釈できます。
  4. 注意：最頻値は確率的な推定です。複数の正解がある場合やノイズがある場合は、最も多い候補だけで正解が確定するとは限りません。最終的には判定条件で確認します。

この4候補の理想モデル：干渉後はメッセージ 7 の確率が100%なので、どの一回の測定でも 7 が出ます。大きな問題や実機では、確率と検証を考えて結果を読みます。

候補振幅振幅²（測定確率）

このモデルの読み方

  1. 回路：どの操作を実行しているかを見る。
  2. 中央：状態全体が、均等な方向から正解方向へ回転する様子を見る。
  3. 右：振幅の符号と高さを見る。確率は振幅を2乗して求める。
  4. 表：同じ状態を数値で確かめる。

これは4候補のグローバー探索を正確に計算する学習用モデルです。実際の量子装置を再現するものではありませんが、回路・ベクトル・振幅・確率・測定は同じ状態データから同期して描画しています。
