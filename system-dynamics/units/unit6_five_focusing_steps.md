# Unit 6 — 5つの集中ステップ：制約をどう直すか

> **対象:** 中学2年生〜一般社会人
> **ゴール（基本編 L3 Teach-Back）:** 改善の5ステップを、Unit 5 の例（リレー・工場）に当てはめて説明できる
> **発展編 L5:** TOC の思考プロセス（CRT・蒸発する雲）への橋渡しを理解できる
> **所要目安:** 基本編 15〜20分 / 発展編 10〜15分

# 基本編（中2〜）

## 1. Hook — 前回の続きから

Unit 5 で「ボトルネック（一番遅いところ）が全体を決める」と学びました。

- リレーでは一番遅い走者
- 工場では一番生産が遅い工程

では、**そのボトルネックをどう直すか**。ここからが今回の話です。同じ事例（リレー・工場）を最後まで使って、「直す手順」を学びます。

## 2. なぜこれを学ぶのか？（Value）

「どこを直すか」が分かっても、**どう直すか**が分からなければ改善は進みません。TOC は、改善の**正しい順序**を5つのステップにしました。

これを知ると、以下のような失敗を防げます。

> 「全部の工程をまんべんなく頑張ったのに、全体は変わらなかった」

「順番」が大事です。**制約を直す→次を探す**の繰り返しで、改善はどんどん進みます。

## 3. 5つの集中ステップ（Reveal）

TOC の生みの親・ゴールドラットが提唱した改善の基本手順です。

| ステップ | 名前 | 内容 |
|---|---|---|
| 1 | **見つける** | 制約（ボトルネック）はどこか |
| 2 | **活用する** | 制約を最大限に使う（無駄な待ちを減らす） |
| 3 | **従属させる** | 他の工程を制約に合わせて動かす |
| 4 | **強化する** | 制約の能力そのものを上げる |
| 5 | **繰り返す** | 制約が動いたら、次の制約を探す |

![fig:5つの集中ステップ — 見つける→活用→従属→強化→繰り返す。制約を直すと次の制約が現れ、また1から回る（循環）](figures/unit6_five_steps.svg)

## 4. 工場の例で追う（Interact）— 5ステップを最後まで

Unit 5 の工場を思い出してください。

```
[工程1: 切る] → [工程2: 磨く] → [工程3: 塗る] → [工程4: 組み立て] → 完成品
```

工程4（組み立て）が「1時間に10個」しか作れず、全体がここで頭打ちになっているとします。

### ステップ1: 見つける

制約はどこか？ → **工程4（組み立て）**。ここに在庫がたまっている（Unit 5 で確認済み）。

### ステップ2: 活用する

「今ある工程4の能力を、無駄なく使う」ことを考えます。

- 工程4の機械が、休憩中や段取り替えで止まっていないか
- 工程4の人が、別の作業をさせられていないか

→ **能力を上げなくても、使っていない時間を無くすだけで生産が増える**ことがあります。ここが最初。

### ステップ3: 従属させる

「他の工程は、工程4に合わせて動かす」ことを考えます。

- 工程1〜3が作りすぎると、工程4の前に在庫がたまるだけ
- 工程1〜3は、工程4が処理できる量だけ作る

→ **作りすぎをやめる**。工程1〜3の頑張りを「制約に合わせて」調整します。

### ステップ4: 強化する

ここで初めて「工程4の能力そのものを上げる」ことを考えます。

- 機械を新しいものにする
- 人員を増やす
- 作業を工夫して速くする

→ 1・2・3の順で考えるからこそ、**無駄な投資**（必要ない強化）を避けられます。ステップ2で空き時間を無くせば、機械を買わずに済むかもしれません。

### ステップ5: 繰り返す

工程4が速くなると、**次に遅い工程がボトルネックになります**（例: 工程2の磨き）。

→ 1に戻って、新しい制約を直す。これを繰り返すと、全体がどんどん速くなります。

> **やってみよう:** 工場の例で、5ステップを順番に追ってみよう。なぜ「強化（ステップ4）」が最後なのか、考えてみよう。

## 5. リレーの例で確かめる（Interact）

Unit 5 のリレーでも、同じ5ステップが使えます。

| ステップ | リレーでの意味 |
|---|---|
| 1 見つける | 一番遅い走者を特定する |
| 2 活用する | その走者の走り方・スタートの仕方を工夫する（能力は変えずに） |
| 3 従属させる | 他の走者は、一番遅い走者に合わせて待つ（無理に飛ばさない） |
| 4 強化する | その走者を鍛える・走順を入れ替える |
| 5 繰り返す | 速くなったら、次の遅い走者を直す |

**順序が大事な理由:** ステップ2（工夫）で十分なら、ステップ4（強化＝時間とお金）は不要。**安い・早い順にやる**のが5ステップの考え方です。

## 6. Check — 確かめてみよう

1. 5ステップの順番を言える？
2. なぜ「強化する（ステップ4）」は最後なのか？
3. ステップ5（繰り返す）で何が起きる？

> **答え（下を見る前に自分で）:**
> 1. 見つける→活用→従属→強化→繰り返す　2. 工夫や調整で足りるなら、お金のかかる強化は不要だから　3. 次のボトルネックが現れるので、1に戻る

## 7. よくある誤解（Misconceptions）

| 誤解 | 正しい理解 |
|---|---|
| 「改善＝いきなり新しい設備・投資」 | まず活用（2）と従属（3）を試す。強化（4）は最後 |
| 「一度直せば終わり」 | 制約は移動する。繰り返し（5）が改善の本質 |
| 「5ステップは工場だけの話」 | リレー・勉強・部活など、どこでも使える手順 |

## 8. Teach-Back — 素人に説明しよう（基本編ゴール）

Unit 5 の例（リレーか工場）を使って、5ステップを説明しよう。

1. **何の話か:** 「一番遅いところを直す手順」の話
2. **部品は何か:** 5つのステップ（見つける・活用・従属・強化・繰り返す）
3. **どう繋がるか:** 制約を直す → 次の制約を探す → 繰り返す
4. **図はどこを見ればいいか:** 工場の工程、ボトルネックの場所
5. **よくある誤解:** いきなり投資するのは間違い。工夫から
6. **素人への一言:** 「リレーで一番遅い人がいるでしょ。まずその人の走り方を直して、足りなければ鍛える。速くなったら次の人だよ」

# 発展編（大学レベル・L4–L5）

> **必要な前提:** math-bridge の **B1〜B5**。Unit 5 発展編（待ち行列）を先に読もう。

## 9. Deepen — 5ステップは「どこに手を打つか」の思考法

5ステップは、数式そのものより**思考の手順**です。しかし、待ち行列（Unit 5 発展編）の数理と組み合わせると、判断が明確になります。

- ステップ2（活用）: 到着率 $\lambda$ とサービス率 $\mu$ の差を、無駄なく詰める
- ステップ4（強化）: $\mu$ そのものを上げる（$\mu > \lambda$ にする）

$$\mu < \lambda \text{ の間は、待ち行列は伸び続ける（発散）}$$

つまり「$\mu$（処理能力）が $\lambda$（到着）より小さければ、何をしても全体は詰まる」— これが制約の数理的な正体です。

## 10. Deepen — TOC の思考プロセスへ（橋渡し）

TOC には、5ステップより深い思考プロセス（Thinking Processes）があります。

| 道具 | 役割 |
|---|---|
| CRT（現状問題ツリー） | 現状の問題（UDE）から根本原因を1つ特定する |
| 蒸発する雲（Evaporating Cloud） | 対立の前提を暴いて、対立を消す |
| FRT（未来問題ツリー） | 解決策が新たな問題を生まないか確認する |

これらは「制約」を「構造・対立」のレベルまで掘り下げる道具です。

> **予告:** Unit 7 で、SD（構造を見る）と TOC（制約を直す）を合わせた総合演習を行います。CRT などの詳細は、そこで「構造図」として自然に登場します。

## 11. Extend — 5ステップを自分の生活に（転移・L4）

> **課題:** 自分の身の回り（勉強・部活・家の手伝い）で、改善したいことを1つ選び、5ステップを順に当てはめてみよう。
>
> 例: 「宿題がいつも遅い」
> 1. 見つける: 一番時間がかかる科目は数学
> 2. 活用する: 数学の前に簡単な科目をやり、集中しやすい時間帯に数学をやる
> 3. 従属させる: 他の科目は数学の量に合わせて計画
> 4. 強化する: 数学の基礎を復習する
> 5. 繰り返す: 次に遅い科目（国語）を直す

## 12. Check-L5 — 発展編の確認

1. 待ち行列が伸び続ける条件は？
2. CRT は何を特定する道具？
3. 5ステップの「強化（4）」が最後なのは、数理的にどう言い換えられる？

> **答え:** 1. $\mu < \lambda$　2. 根本原因（Core Constraint）　3. まず $\mu$ の無駄をなくし（活用・従属）、それでも $\mu < \lambda$ なら $\mu$ を上げる（強化）、という効率の順序

---

## まとめ（Takeaway）

- 5つの集中ステップ: **見つける→活用→従属→強化→繰り返す**
- 順序が大事: 工夫（2・3）→ 投資（4）。安い順にやる
- 制約は移動する。繰り返し（5）が改善の本質
- 数理: $\mu$（処理能力）が $\lambda$（到着）より小さい限り、待ちは伸び続ける
- 次回は SD と TOC を合わせて、総合演習

> **次回予告 (Unit 7):** 構造を見て（SD）、制約を直す（TOC）。総合演習。
