この章では、現場の混沌とした日本語の要望が、どのように「3D直方体」と「2値マトリクス（0/1表）」に整理され、 最終的にPythonのデータ構造（2D配列・辞書）へと変換されるのか、その入力構築プロセスを徹底的にマスターします。

シフト作成で最も重要なスキルは、「人間の言葉（ワガママや現場ルール）」を「0と1の判定式」に分解し、そのまま「CP-SATコード」に落とし込む変換力です。

思考の土台

最適化プログラミングを始めるとき、初学者が最もつまずくのが「現実のバラバラな要望を、どうやって数理モデルの形に整理すればいいのか？」というデータの作り方です。
ここでは、現場の生々しいやり取りからPythonで扱えるデータ構造（マトリクス）が完成するまでの全プロセスを、4つの段階で追体験してみましょう！

第1段階：スタッフから届く「生の声」（自然言語のメモやLINE）

毎月のシフト締め切り日、管理者（リーダー）の手元には以下のようなLINEメッセージや付箋が集まります。

👩 Alice (子育て中)
「水曜日は子供のピアノの発表会があるので、絶対に休みにしてください！」
👨 Bob (アウトドア派)
「今週末（土・日）に友人とキャンプを予定しています。土日の連休希望です！」
🧑 Charlie (通院あり)
「月曜日の午前に定期検診の予約が入っているため、月曜休みを希望します。」
👱 Dave (稼ぎたい派)
「休みは平日いつでも良いです。金曜の夜勤手当を稼ぎたいので夜勤に入れてください！」

第2段階：すべての可能性を網羅する「3次元の白紙グリッド」を定義する

コンピュータには「感情」や「言葉のニュアンス」は一切伝わりません。そこで、シフト表のすべてのマス目を
「スタッフ（4人） × 日付（7日） × シフト種別（日勤/夜勤/休の3種） ＝ 計84個のスイッチ」
として空間を構造化します。

staff = ["Alice", "Bob", "Charlie", "Dave"]
days = ["月", "火", "水", "木", "金", "土", "日"]
shifts = ["D", "N", "O"] # D:日勤, N:夜勤, O:休日

# 84個のマス目の1つひとつに (スタッフ, 日付, シフト) の住所がつく！
(Alice, 水, O) ➔ 「Alice の 水曜日 は 休日か？」を表すスイッチ

第3段階：生の声の該当するマスに「1」を立てる（要望マトリクスの誕生）

スタッフの希望が書かれているマスに「1（希望あり）」を、何も指定がないマスには「0（どちらでも良い）」を埋めていきます。

スタッフ 月火水木金土日 翻訳された要望の意味
Alice 00 1 (休) 0000 水曜に「休」スイッチをONにしてほしい
Bob 00000 1 (休) 1 (休) 土・日両方に「休」スイッチをONにしてほしい
Charlie 1 (休) 000000 月曜に「休」スイッチをONにしてほしい
Dave 0000 1 (夜) 00 金曜に「夜勤」スイッチをONにしてほしい
🐍 Pythonコードでこのマトリクスを定義する具体例（2つの王道スタイル）

この「0と1の表」は、Pythonでは以下のどちらの形式でも直感的に書くことができます：

スタイルA: 見た目そのままの2次元配列 (0/1 Matrix) 
# スタッフ × 日付の「希望休(O)」マトリクス
#          月, 火, 水, 木, 金, 土, 日
request_matrix = {
    "Alice":   [0,  0,  1,  0,  0,  0,  0],  # 水休
    "Bob":     [0,  0,  0,  0,  0,  1,  1],  # 土日休
    "Charlie": [1,  0,  0,  0,  0,  0,  0],  # 月休
    "Dave":    [0,  0,  0,  0,  0,  0,  0],  # なし
}

# 利用側: マトリクスで1のマスだけペナルティに変換
for s, row in request_matrix.items():
    for d_idx, is_req in enumerate(row):
        if is_req == 1:
            d = days[d_idx]
            penalties.append(10 * (1 - x[s, d, "O"]))
スタイルB: 実務で最も好まれる「辞書形式」 (Sparse Map) 
# (スタッフ, 日付) ➔ 希望シフト のマッピング
# ※ 0（こだわりなし）は省略できるため実務で超便利！
requests = {
    ("Alice",   "水"): "O",  # 水曜休み
    ("Bob",     "土"): "O",  # 土曜休み
    ("Bob",     "日"): "O",  # 日曜休み
    ("Charlie", "月"): "O",  # 月曜休み
    ("Dave",    "金"): "N",  # 金曜夜勤手当
}

# 利用側: 辞書から直接ペナルティに変換
for (s, d), desired_shift in requests.items():
    penalties.append(10 * (1 - x[s, d, desired_shift]))

第4段階：Pythonコードでの保持方法と「不満度（ペナルティ）の数式化」

Pythonプログラムでは、この要望を (スタッフ, 日付, 希望シフト) をキーにした辞書やタプルリストで直感的に保持します：

# 1. 現場から集まった要望リスト（これが要望マトリクスの実体！） requests = [ {"staff": "Alice", "day": "水", "shift": "O", "weight": 10}, # 水曜休 {"staff": "Bob", "day": "土", "shift": "O", "weight": 10}, # 土曜休 {"staff": "Bob", "day": "日", "shift": "O", "weight": 10}, # 日曜休 {"staff": "Charlie", "day": "月", "shift": "O", "weight": 10}, # 月曜休 {"staff": "Dave", "day": "金", "shift": "N", "weight": 10}, # 金曜夜勤 ] # 2. マトリクスからペナルティ（目的関数）への自動変換！ penalties = [] for req in requests: s = req["staff"] d = req["day"] sh = req["shift"] w = req["weight"] # x[s, d, sh] が 1（希望通り）なら、(1 - 1) = 0点（不満なし） # x[s, d, sh] が 0（叶わず）なら、(1 - 0) * weight = 10点（ペナルティ発生！） penalties.append(w * (1 - x[s, d, sh])) # 全員の不満合計を最小化せよ！ model.Minimize(sum(penalties))
💡 ここが美しさの頂点！
w * (1 - x) という極めてシンプルな1行の数式で、
「叶えばペナルティ0、叶わなければペナルティ加算」 という人間の「わがまま・願望」が完璧に数理化されました。
あとはCP-SATが、第3章で学んだMaxSAT二分探索で「不満ペナルティの合計が最も小さくなる妥協シフト」を一瞬で探索してくれるのです！

🎓 第4章の重要チェックポイント（データ入力の準備完了！）

  • 3次元の直方体: スタッフ $\times$ 日付 $\times$ シフト種別 の立体グリッドとして変数を定義する。
  • マトリクスの役割: 「要望」や「必要人数」は、この直方体のスライス（断面）に対するデータ（配列または辞書）として表現する。
  • ハードとソフトの分離: 絶対に守る「必須条件（必要人数など）」と、できれば叶えたい「希望休（ペナルティ化）」をデータ作成の段階で明確に分ける。
