# 学習設計書 — 動機主導 × アダプティブ数学教材

> **Status:** Draft v0.2（2026-07-23）— **D1–D5 決定済・実装前設計フェーズ**  
> **Scope:** 教材シリーズ共通の学習アーキテクチャ。第一実装題材はフーリエ変換。  
> **ゴール状態:** 学習者が「素人に教えられる」深さまで、理論と数式の意味を自分の言葉と操作で再現できる。  
> **関連:** `SKILL_GRAPH.md` / `CHECK_ITEMS.md` / `nodes/` / `IMPLEMENTATION_SPEC.md`

## 0. 一文定義

**魅力的な現実ゴールから逆算した前提グラフを、単元別マスタリーに応じて動的に辿らせる。理解確認は「数式キーボード入力」に依存せず、意味・構造・予測・教え返しで測る。**

---

## 1. 設計原則（非交渉）

| ID | 原則 | 意味 | 禁止 |
|----|------|------|------|
| P1 | **動機主導（Motivation-First）** | 「何に使うか」の体験を最初に置き、必要最小の数学へ降りる | 目的不明の単元積み上げ |
| P2 | **本質・数式を逃がさない** | ビジュアルは入口。最終的に式の各記号の役割を言える | アニメだけで終わらせる |
| P3 | **Teach-Back が習熟の定義** | 「解ける」ではなく「素人に手順と理由を説明できる」 | 選択問題の正答率だけを完了条件にする |
| P4 | **単元グラフ適応** | 習熟済みは飛ばし、未習熟は必要な節だけ戻る | 全員同一一本道 |
| P5 | **入力摩擦の最小化** | 確認UIはタップ・ドラッグ・予測・並べ替えが既定 | 自由記述の数式入力を必須にしない |
| P6 | **効率は枝刈りで出す** | 既知を再講義しない／未知だけを最短閉路で埋める | 網羅講義の再生 |

補足: ユーザー表記の「同期主導」は本設計では **動機主導（Motivation-Driven）** として解釈する。

## 2. 対象と到達像

### 2.1 対象

- **主:** 中学3年〜社会人（学び直し・実務入口）
- **想定差:** 三角比既習／未習、複素数既習／未習、コード経験の有無が混在

### 2.2 到達像（シリーズ共通ルーブリック）

| レベル | 名前 | 判定（すべて満たす） |
|--------|------|----------------------|
| L0 | 体験 | デモを操作し、「何が起きているか」を日常語で言える |
| L1 | 構造 | 部品（円・波・係数・周波数等）の役割を指差し説明できる |
| L2 | 記号 | 式の各項を部品に対応づけ、「なぜその形か」を説明できる |
| L3 | **Teach-Back（目標）** | 素人役に 3〜7 分で教え、典型誤解を自分で訂正できる |
| L4 | 転移（任意） | 未知の近い問題／コード／別領域へ自分で橋を架けられる |

**モジュール完了条件 = 対象ノードが L3。** L4 はボーナス経路。

## 3. 学習の全体形（学習者視点の1サイクル）

```
[Hook] 現実ゴールの体験（音・画像・圧縮など）
   ↓
[Map]  「ゴールまで足りないピース」を地図で見せる
   ↓
[Probe] 入口診断（粗い）→ 開始ノード決定
   ↓
┌─[Node Loop]────────────────────────────────────────┐
│  Reveal（短説明）→ Interact（操作）→ Predict（予測） │
│  → Check（非数式入力確認）→ Teach-Back ミニ         │
│  → Mastery 更新 → 次ノード or ギャップ補修          │
└────────────────────────────────────────────────────┘
   ↓
[Capstone] ゴール課題（圧縮・分解・再構成など）+ 本番 Teach-Back
   ↓
[Export]  dual成果: 自分用チートシート + 教え方スクリプト
```

時間効率の核心は **Node Loop の短サイクル** と **既習スキップ**。

## 4. 知識の単位：ノードとエッジ

### 4.1 ノード（Skill Node）

1ノード = 15分前後で L3 まで上げられる最小の意味単位。

必須メタデータ:

```yaml
id: FT-CIRCLE-1
title: 等速円運動とサイン波
goal_link: "波は円の影として取り出せる"
prerequisites: [FT-RATIO-1]   # エッジ
mastery_default: unknown      # unknown | L0..L3
layers:
  visual: required
  symbolic: required
  code: optional
misconceptions:
  - "円が速いと波長が伸びる"   # 実際は周波数
checks: [C-pred-phase, C-map-terms, C-teach-30s]
remediation: [FT-RATIO-1, FT-ANGLE-1]
```

### 4.2 エッジ（依存）

- **hard:** 未習なら進めない（例: 角度 → 円運動）
- **soft:** 弱くても前進可。つまずき時だけ戻る（例: 複素数表記）
- **motivational:** 学習動機を保つための先行体験（Hook）

### 4.3 3レイヤーは「別コース」ではなく「同じノードの面」

| Layer | 役割 | いつ使う |
|-------|------|----------|
| Lyr-V 視覚 | 存在証明・直感 | 常に入口。L0–L1 |
| Lyr-S 数理 | 記号と証明の骨格 | L2–L3 必須 |
| Lyr-C コード | 実行可能性・転移 | L3強化 / L4 |

学習者は「Vだけコース」を選べない。**Vで掴み、Sで定着**が既定。Cは選択強化。

## 5. アダプティブルータ（習熟に応じた自由なルート）

### 5.1 状態

各ノード: `unknown | struggling | learning | mastered(L3) | stale`

- **stale:** 長期未使用。Capstone 前に 1 問だけ再確認
- **struggling:** 同一ノードで Check 連続失敗 → 前提へ強制バックリンク

### 5.2 ルーティング規則（優先順）

1. **ゴール逆算のクリティカルパス**上の未マスタを列挙  
2. クリティカル上で **既マスタはスキップ**  
3. soft 依存は「失敗するまで仮定マスタ」  
4. 連続失敗 2 回 → hard 扱いで前提ノードへ  
5. 学習者の明示希望（「数式から」「図から」）は **同一ノード内の提示順**だけ変える（到達基準は不変）  
6. 時間予算モード: `sprint(25m)` / `deep(60m)` / `teach(90m)` でノード粒度を切る

### 5.3 学習者に見えるもの

- **現在地マップ**（ゴールまでの残りノード数と ETA）
- **なぜ今これをやるか**（1文: ゴールとの接続）
- **スキップした根拠**（「三角比: 入口診断で L3 相当」）
- **いつでも戻れる前提リンク**（恥のない再学習）

### 5.4 入口診断（短い・低摩擦）

- 5〜8 問、数式入力なし
- 出力は詳細偏差値ではなく **開始ノード集合**
- 「わからない」を正解扱いの選択肢に入れ、推測ノイズを減らす

## 6. 理解確認設計（最重要課題への回答）

### 6.1 課題の定式化

> 学習者に理解を確認したいが、**数式のキーボード入力は認知負荷・UI負荷・誤判定が大きく、中3〜社会人の広い層で破綻しやすい。**

したがって確認は **「式を書けるか」ではなく「式の意味構造を操作・説明できるか」** に置く。

### 6.2 確認モダリティ・ポートフォリオ（数式自由入力を使わない）

| コード | モダリティ | 測る力 | 例（フーリエ） |
|--------|------------|--------|----------------|
| M1 | **Predict-Observe** | 因果モデル | Nを増やす前に波形を予言 → 実行 |
| M2 | **Parameter → Meaning** | 記号対応 | スライダ「この係数」⇔「この円の半径」を結線 |
| M3 | **Term Mapping** | 式の構造 | カードを式スロットへ（∫, e^{iωt}, c_n…） |
| M4 | **Defect Diagnosis** | 誤概念 | 壊れた説明／壊れた図のどこが誤りか |
| M5 | **Order the Proof** | 論理順序 | 証明ステップを並べ替え |
| M6 | **Contrast Cases** | 境界条件 | 「周波数だけ違う2波」の違いを言葉+操作 |
| M7 | **Teach-Back 30s/3min** | L3 本番 | 音声/テキスト/箇条書きテンプレ |
| M8 | **Faded Worked Example** | 再生 | 穴埋めは **チップ選択**（自由LaTeX禁止が既定） |
| M9 | **Gesture on Canvas** | 空間理解 | 「1周期をドラッグで示す」「直交をタップ」 |
| M10| **Code Trace（任意）** | 実行意味 | どの行が c_n かハイライト |

**既定禁止:** 空の数式エディタへの自由入力をゲートにする。  
**例外許可:** 希望者のみ「Challenge: 手で書け」モード（採点は構造一致の緩い正規化）。

### 6.3 Teach-Back の型（目標習熟の測定器）

固定テンプレ（学習者は穴を埋める／カードを選ぶ）:

1. **何の話か（ゴール）** — 1文  
2. **部品は何か** — 3つまで  
3. **どう繋がるか** — 因果を1本  
4. **式はどこを見ればいいか** — 指差し or カード  
5. **よくある誤解** — 1つ訂正  
6. **素人への一言** — 比喩1つ

評価: ルーブリック自動下書き + （将来）LLM補助の観点チェック。  
初期実装は **チェックリスト自己評価 + 模範解答の差分ハイライト** で十分。

### 6.4 「数式を理解している」ことの操作的定義

次の **すべて** ができれば L2、Teach-Back まで通れば L3:

- 式中の各記号を、画面上のオブジェクトに対応づけられる  
- 「この記号を変えると何が変わるか」を予測し、デモで一致させられる  
- 「なぜ割り算／積分／和が出るか」を、目的語で説明できる（計算手順の暗唱ではない）

| Pattern | 学習効果 | 実装メモ |
|---------|----------|----------|

| Equation Hotspots | 式の部分クリックでハイライト | M2/M3 |

| Teach Desk | 30秒説明UI | M7 |

**UI原則:** 1画面1操作目的。説明文は120字以内＋「もっと」展開。

## 8. 学習効率を飛躍させるレバー

効率は「早口」ではなく **無駄の削除** で出す。

| レバー | 仕組み | 期待効果 |
|--------|--------|----------|
| E1 ゴール逆算 | 必要ノードだけ残す | 学習量 1/2〜1/5（単元依存） |
| E2 既習スキップ | 診断＋自己申告＋確認1問 | 再講義時間の削除 |
| E3 失敗時だけ前提 | soft依存の遅延束縛 | 過剰復習の削除 |

## 9. 第一題材への落とし込み — フーリエ変換

### 9.1 動機フック（冒頭5–10分）— **決定: 画像（JPEG直感）**

- 同一写真の「粗い ⇔ 細かい」スライダ（低周波だけ／高周波も）  
- 体験の結論: **細かい模様＝高い周波数成分。捨てると軽くなる＝圧縮**  
- 問い: **「画像を“波の重なり”に分解できたら、何を残し何を捨てるか選べるのでは？」**  
- 音フィルタは Phase 2 の転移フック（任意）

### 9.2 ゴール逆算スキルグラフ — **決定: 実数完走 → 後で e^{iθ}**

正本の表は `SKILL_GRAPH.md`。縦一列の骨格:

```
[Hook: 画像 JPEG 直感] FT-HOOK-1
    ↓
FT-WAVE-1  波（振幅・周期・位相）※画像行の明るさ変化として導入可
    ↓
FT-RATIO-1 三角比ミニ（必要な人だけ）
    ↓
FT-CIRCLE-1 円運動 → サイン
    ↓
FT-SUPER-1  重ね合わせ
    ↓
FT-SERIES-1 足し算で任意波形（実数 sin/cos）
    ↓
FT-ORTHO-1  直交・「似ている度」直観
    ↓
FT-COEFF-1  係数の決まり方（実数経路で完走）
    ↓
FT-APP-1    圧縮＝係数を削る（画像へ再接続）
    ↓
FT-CAP-1    Capstone + Teach-Back（テキストテンプレ）【実数経路の完了点】
    ↓
FT-EULER-1  e^{iθ} 再接続（任意・L4寄り）
    ↓
FT-TRANSFORM-1 連続/離散の見取り図（任意拡張）
```

**分岐**

- 三角比が弱い → `FT-RATIO-1` のみ挿入（網羅的高校数学はしない）  
- 複素は **FT-CAP-1 後**まで出さない（実数完走が主経路）  
- コード好き → 各ノード Lyr-C 枝（MVPでは任意）

### 9.3 Layer 対応

| Layer | 現状 | 次の設計ターゲット |
|-------|------|--------------------|
| Lyr-V | `index.html` 方形波合成 | 画像Hook、予測、成分ON/OFF、式ホットスポット |
| Lyr-S | 未整備 | 実数 sin/cos の意味カード + M3/M5（複素は後段） |
| Lyr-C | 未整備 | 同一概念の 20 行 JS（MVP後） |

### 9.4 フーリエにおける「数式入力なし確認」の具体例

1. **係数カードを円の半径にドラッグ**（大きい係数＝大きい円）  
2. **「Nを増やすと角がどうなるか」を予言** → アニメ一致  
3. **壊れた説明:**「円を速く回すと波が高くなる」→ 誤り箇所をタップ  
4. **Teach-Back（テキスト）:**「JPEGは何を捨てている？」を6欄テンプレで説明
